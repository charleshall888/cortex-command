# Specification: remove-claude-agent-sdk-dependency

## Problem Statement

Cortex depends on the `claude-agent-sdk` PyPI package to spawn agents, and that dependency broke every install of every cortex release on 2026-09-16: the publisher yanked the exact version cortex pinned, with a notice that it will be deleted on or after 2026-09-19. This is a standing policy, not an incident — 30+ releases from 0.0.23 through 0.2.99 carry the same notice, because each wheel is ~90–103 MB (almost entirely a bundled `claude` binary) and the project is over its storage quota. The bundled binary is the part cortex least wants: `resolve_claude_cli()` already routes around it in favour of the operator's own `claude` (ADR-0014), and the overnight orchestrator already spawns bare `claude -p`. So cortex pays 216 MB installed and a recurring supply-chain fuse for a JSON-lines parser it uses at two call sites. Spawning the operator's `claude` directly — the integration path Anthropic's own docs prescribe for non-SDK callers — removes the fuse, the download, and one dependency. Everyone who installs cortex benefits; overnight operators benefit most, because the auto-installer's reinstall is what fails first when a pinned release disappears.

## Phases

- **Phase 1: Spawn `claude` directly** — one spawn-and-parse seam replaces `query()` at both call sites, with the SDK still installed and unused. Phase 1 alone does not fix the install outage: the dependency is still declared and still resolved on every auto-reinstall, so the motivating problem closes only at Phase 2. What Phase 1 buys is landing the risky behaviour change on its own, where it can be reverted without touching packaging.
- **Phase 2: Delete the dependency and collapse the install** — drop `claude-agent-sdk`, move the dashboard stack into the base install, and correct every surface that names the SDK.
- **Phase 3: Cover the drift the SDK used to absorb** — the checks that see CLI-schema churn and install-time breakage.

## Requirements

1. **One spawn seam serves both call sites**: a single internal entry point spawns `claude` and yields parsed stream-json frames; `cortex_command/pipeline/dispatch.py` and `cortex_command/discovery.py` both consume it, and neither imports `claude_agent_sdk`. Acceptance: `grep -c "claude_agent_sdk" cortex_command/pipeline/dispatch.py cortex_command/discovery.py` = 0 for both, and `grep -rn "query(" cortex_command/pipeline/dispatch.py cortex_command/discovery.py` shows no SDK call. **Phase**: Spawn `claude` directly

2. **Every option cortex sets today reaches the CLI unchanged**: turn limit, budget, cwd, permission mode, allowed tools, system prompt, env, settings file, and effort. Acceptance: a test asserts the built argv contains `-p`, `--output-format stream-json`, `--verbose`, `--max-turns`, `--max-budget-usd`, `--permission-mode`, `--allowedTools`, `--system-prompt`, `--settings`, `--effort` with the values the tier config supplies (grounding: `cortex_command/pipeline/dispatch.py:799-817`). **Phase**: Spawn `claude` directly

3. **The prompt travels on stdin, not argv**: the child receives the prompt on standard input and cortex writes nothing else to it. Acceptance: the argv test above asserts no prompt-shaped positional argument, and a test feeds a prompt larger than 128 KiB through the seam against a fake CLI and asserts it arrives intact. Rationale recorded in Technical Constraints. **Phase**: Spawn `claude` directly

4. **Stdout is read line-by-line with a cap at or above 1 MiB**: a single frame larger than Python's 64 KiB stream default must not fail the dispatch. Acceptance: a test drives the parser with a synthetic 256 KiB `assistant` frame and asserts the text is collected and no exception is raised (grounding: the largest real recorded frame in `cortex/lifecycle/sessions/*/orchestrator-round-*.stdout.json` is 41,412 bytes). **Phase**: Spawn `claude` directly

5. **Stderr is drained concurrently with stdout**: neither stream may block the other. Acceptance: a test runs the seam against a fake CLI that writes >128 KiB to stderr and >128 KiB to stdout and asserts the run completes; stderr redaction, the 64 KiB tail cap and the 100-line cap are preserved (grounding: `dispatch.py:786-797`). **Phase**: Spawn `claude` directly

6. **The child's environment is the parent's, minus `CLAUDECODE`, plus cortex's overlay**: the overlay must not become the child's whole environment. Acceptance: a test asserts the spawn environment contains `PATH` and `HOME` from the parent, does not contain `CLAUDECODE`, and contains every key cortex sets (grounding: `dispatch.py:682-701`). **Phase**: Spawn `claude` directly

7. **The run ends on process exit, not on the first `result` frame**: cortex parses every line and takes the last `type == "result"`. Acceptance: a test feeds frames in which a `system` frame follows the `result` frame and asserts the run consumed both and reported the result's fields (grounding: verified live — frame order ends `result` then `hook_response`; the result frame's first key is `duration_api_ms`, so no prefix fast-path may be used). **Phase**: Spawn `claude` directly

8. **Unrecognized frame types and non-JSON lines are skipped, never fatal**: a frame type cortex does not know, a line that is not JSON, and a JSON line without `type` each leave the run unaffected. Acceptance: a test feeds one of each and asserts the dispatch still succeeds with the expected output. **Phase**: Spawn `claude` directly

9. **Only assistant text enters the keyword corpus**: `system`, `init`, hook, and rate-limit frame text must not reach the free-text that `classify_error` keyword-scans. Structured fields from those frames are a separate input and are read deliberately (see the API-fault requirement below). Acceptance: a test drives a failing dispatch whose `system/init` frame carries a `cwd` containing `failing-tests` and asserts the classification is not `agent_test_failure`; a second test asserts a `rate_limit_event` frame still reaches classification through its structured fields, not through the corpus (grounding: `dispatch.py:352-366`, `:876-878`). **Phase**: Spawn `claude` directly

10. **The error taxonomy is preserved without SDK exception types**: every one of the eleven `ERROR_RECOVERY` keys reachable today stays reachable, including `agent_confused`, which is produced only inside the `ProcessError` arm this change deletes. Acceptance: one test per key drives a dispatch to that `error_type` and then drives `cortex_command/pipeline/retry.py` with the result, asserting the action it actually takes — not an `ERROR_RECOVERY` dict lookup, which is an untouched module-level dict and so passes at HEAD. The `effort_unsupported` case must assert the clamp that `retry.py`'s explicit string comparison performs, and a key the implementation chooses to retire instead of preserve is recorded under Non-Requirements with its reason (grounding: `dispatch.py:323-347`, `:480-543`, `:515`, `:528`; `retry.py:321`, `:375`). **Phase**: Spawn `claude` directly

11. **A `claude` that cannot be spawned pauses for a human rather than retrying**: a missing, non-executable, or unspawnable binary classifies as `infrastructure_failure` (recovery `pause_human`), never `unknown`/`retry`. Acceptance: a test points the seam at a non-existent path and asserts `error_type == "infrastructure_failure"`, and a second asserts the operator-facing message names the binary and says to install Claude Code. **Phase**: Spawn `claude` directly

12. **A failed run is named for its real cause, and an API-wide fault still halts the session.** `is_error: true` with a non-budget cause must not classify as `budget_exhausted`, *and* it must still stop the overnight round loop: today `budget_exhausted` is the only `error_type` an `is_error` frame can produce, and it is what reaches `_SESSION_HALT_ERROR_TYPES` → `global_abort_signal` → `state.paused_reason` → the round-loop break, the operator notification, and the paused banner. So the new classification must distinguish (a) budget exhaustion, (b) an API-wide fault — auth failure, `terminal_reason: "api_error"`, rate limit — which is session-halting, and (c) a per-feature failure, which retries. Acceptance: a test feeds `is_error: true`, `subtype: "success"`, `terminal_reason: "api_error"` and asserts the classification is not `budget_exhausted` **and** that its `error_type` is a member of `_SESSION_HALT_ERROR_TYPES`; a second test feeds the budget subtype and asserts `budget_exhausted`; a third drives the halt chain end to end and asserts `state.paused_reason` is set and the round loop stops (grounding: `dispatch.py:898-903`, `:965`; `overnight/feature_executor.py:76,774`; `overnight/orchestrator.py:419,596`; `overnight/runner.py:2704,3342`; `overnight/report.py:598`). **Phase**: Spawn `claude` directly

13. **Turn-limit exhaustion is still detected**: the existing `stop_reason` + `num_turns` signature keeps producing `turn_limit_exhausted`. Acceptance: a test feeds `stop_reason: "tool_use"` with `num_turns` at the configured cap and asserts `turn_limit_exhausted` (grounding: `dispatch.py:458-477`; the incident at `:339-345` is what this guards). **Phase**: Spawn `claude` directly

14. **Every failure path carries diagnostics**: any `DispatchResult` with an `error_type` reports `child_stderr`, `exit_code` and `cwd`. Today the `is_error` path is the one failure that returns none, which was survivable only because it never retried; the API-fault split moves the most common real failure onto a retrying path, where `retry.py` writes `child_stderr` into the learnings file the next attempt reads and the morning report renders nothing without one of the three keys. Acceptance: a test asserts a populated `diagnostics` on the result-frame failure and on a non-zero-exit failure (grounding: `dispatch.py:961-971` vs `:1024-1034`; `retry.py:295-297`; `overnight/report.py:2400`). **Phase**: Spawn `claude` directly

15. **Real-CLI behaviour is verified once before Phase 1 lands**: an interactive verification run drives a real dispatch through the seam under a per-dispatch sandbox settings file that denies a write, and confirms the kernel denial, the tool-result frame, and a successful result frame. `Interactive/session-dependent: costs a real model call (~$0.27 observed) and requires an authenticated CLI, so it is run by the implementer and recorded in the phase notes, not in CI.` **Phase**: Spawn `claude` directly

16. **The dependency is gone from the package metadata**: `claude-agent-sdk` appears in no dependency list. Acceptance: `grep -c "claude-agent-sdk" pyproject.toml` = 0 and `grep -c "claude-agent-sdk" uv.lock` = 0. **Phase**: Delete the dependency and collapse the install

17. **The dashboard installs with the base package**: a bare install with no extras can serve the dashboard. Acceptance: `uv pip compile` on a requirements file naming the built wheel with **no** extras resolves `fastapi`, `uvicorn`, `jinja2`, `markdown`, and `starlette`; the same compile against `[all]`, `[dashboard]`, and `[overnight]` each prints **no** `does not have an extra` warning on stderr — the warning is the load-bearing half, since an undeclared extra still exits 0. **Phase**: Delete the dependency and collapse the install

18. **Dead extra-guards are deleted, and the macOS app stops arriving unasked.** The dashboard install hints and the `uvicorn` capability probe go — but that probe is currently the *only* thing keeping the applet out of a non-dashboard install, and `cortex init` calls `ensure_app()` unconditionally, so deleting it alone would run `osacompile` and `codesign` and drop an app into `~/Applications` for every macOS operator, including backlog-only users. Acceptance: `grep -c "requires the optional 'dashboard' extra" cortex_command/cli.py` = 0, `grep -c "find_spec(\"uvicorn\")" cortex_command/dashboard/macapp.py` = 0, `grep -c "ensure_app" cortex_command/init/handler.py` = 0, and a test asserts `cortex init` in a fresh repo creates no bundle at the app path (grounding: `init/handler.py:403`; `dashboard/macapp.py:146`). **Phase**: Delete the dependency and collapse the install

## Non-Requirements

- **The overnight orchestrator spawn is not rewritten.** `runner.py` already spawns `claude -p` directly; its file-backed stdout and watchdog stay as they are.
- **No `--bare` adoption.** It disables hooks, CLAUDE.md discovery, plugins, and auto-memory, all of which dispatches rely on, and it forces API-key auth.
- **No control-protocol client.** Hooks, `can_use_tool`, SDK-MCP servers, resume, and interrupt are not reimplemented; cortex uses none of them.
- **No new timeout or cancellation policy.** None exists today; adding one is separate work.
- **No retargeting of the duplicated verdict parser.** `review_dispatch.py` / `review_brief.py` duplicate a parser to avoid a transitive SDK import; the reason expires with this change, but the cleanup is its own ticket.
- **Windows support.** Unchanged and still out of scope.

## Edge Cases

- **`claude` is absent, or present but not executable**: classify as `infrastructure_failure`, pause for a human, and name the path searched.
- **The child writes a frame larger than 64 KiB**: parsed normally (R4).
- **A frame arrives after the `result` frame**: consumed; the run ends at process exit (R7).
- **The child exits non-zero with a well-formed result frame**: the frame's fields decide the classification; the exit code alone does not.
- **The child exits non-zero with no result frame at all**: `task_failure` carrying the captured stderr, not `unknown`.
- **`is_error: true` with `subtype: "success"`**: not a budget failure (R12).
- **The prompt exceeds a megabyte**: stdin carries it; the CLI's documented stdin cap is 10 MB and cortex's largest observed prompt is 56 KB.
- **The dashboard runs on a machine with no Claude Code at all**: it serves normally; only overnight and dispatch fail, with the missing-binary message.
- **An API-wide fault lands mid-round** (expired auth, provider outage, rate limit): the session halts once with the cause named, rather than retrying every feature against a dead API.
- **A macOS operator who only uses the backlog runs `cortex init`**: no app is compiled and nothing is written to `~/Applications`.
- **A user installs `cortex-command[overnight]` after the extra is emptied**: resolves and installs; the extra provides nothing.

## Changes to Existing Behavior

- **MODIFIED**: agents are spawned by cortex as `claude -p --output-format stream-json --verbose` with the prompt on stdin, instead of through `claude_agent_sdk.query()`.
- **MODIFIED**: error classification keys on process exit plus result-frame fields rather than SDK exception types.
- **MODIFIED**: an `is_error` result with a non-budget cause no longer pauses the session as a budget exhaustion; an API-wide fault still halts the session, under a name that says what happened.
- **MODIFIED**: `cortex init` no longer creates the macOS dashboard app; the first `cortex dashboard` run does.
- **MODIFIED**: the base install now carries the dashboard stack; `[all]`, `[dashboard]`, `[overnight]` remain valid names that add nothing.
- **REMOVED**: the `claude-agent-sdk` dependency, the SDK-bundled CLI branch, the SDK import guards and their install hints, and the `sys.modules` SDK stub.
- **ADDED**: an opt-in live-CLI test and a scheduled install-resolve check.

## Technical Constraints

- The stream-json event schema is not versioned. Anthropic's documented guidance is to feature-detect through the `system/init` `capabilities` array and to ignore unknown fields and values; cortex must read only the fields it needs and tolerate everything else.
- `--max-turns` is accepted by `claude` 2.1.273 but does not appear in `--help`; an unknown flag exits 1 with `error: unknown option`, which is the detection cortex gets.
- Errors arrive on stdout inside the JSON envelope, not on stderr; stderr carries warnings such as the `--effort` warn-ignore line that `dispatch.py` already scans for.
- SIGTERM mid-turn loses the turn and exits 143; SIGINT ends a turn cleanly. Relevant to any future cancellation work, not to this change.
- Verified live before writing this spec: stdin prompt + `--output-format stream-json --verbose --max-turns 3 --permission-mode bypassPermissions --settings <denying file> --effort low` runs, the kernel denies the `denyWrite` target (`operation not permitted`), the target stays byte-identical, and the run ends `result` with `is_error: false`, `subtype: "success"`, `num_turns: 2`.
- `uv tool install` from a git ref ignores `uv.lock`, so the `pyproject.toml` bounds are the only governance reaching installs (`cortex/requirements/project.md:54`).

## Proposed ADR

### Proposed ADR: 0038-cortex-spawns-the-operator-claude-directly

Context: cortex reached the Claude CLI through `claude-agent-sdk`, whose wheels bundle a ~90 MB `claude` binary that cortex already routes around, and whose publisher yanks and deletes old releases to stay under a storage quota — which broke every install on 2026-09-16. Decision: cortex spawns the operator's own `claude` as a subprocess (`-p --output-format stream-json --verbose`, prompt on stdin) and parses the JSON-lines stream itself, reading only the fields it needs and skipping everything else; `resolve_claude_cli()` keeps its system search, including the non-PATH fallbacks, and loses only the SDK-bundled branch. This supersedes the bundled-vs-system half of ADR-0014 while preserving its effort-by-outcome handling, and amends ADR-0032's mechanism wording (the observed model is read from the `assistant` frame, not from `AssistantMessage`). Trade-off: cortex trades a pinned, range-tested Python contract for an unversioned CLI surface it must tolerate defensively — in exchange it drops 216 MB, one dependency, and a recurring supply-chain fuse, and it takes the integration path Anthropic's own documentation prescribes for non-SDK callers.

### Proposed ADR: 0039-one-install-shape-with-the-dashboard-in-the-base

Context: the extras split exists because the overnight stack pulled a 197 MB SDK; with that gone, the only optional weight is the ~17 MB dashboard stack, while the auto-installer has always installed `[all]` anyway, so in practice every operator already carries it. Decision: the dashboard's dependencies move into the base install, and `[all]` / `[dashboard]` / `[overnight]` stay declared but empty so every published install command — including the plugin auto-installer's version-locked argv — keeps resolving. Trade-off: a backlog-only user downloads ~17 MB they may not use, and the extra names survive as vestigial vocabulary; in exchange there is one install shape to document and test, the dashboard works for operators who do not use Claude Code at all, and a class of "reinstalled without the right extra" failures disappears. One consequence is not inert and is handled rather than accepted: the presence of `uvicorn` is today the predicate that decides whether an operator wants the macOS app at all, so the collapse would otherwise hand every macOS operator a compiled applet at `cortex init` time — the app therefore moves behind the first `cortex dashboard` run, which is an expressed intent.
