# Research: Remove the claude-agent-sdk Python dependency and spawn `claude -p --output-format stream-json` directly

Clarified intent: cortex stops depending on the `claude-agent-sdk` PyPI package and spawns the operator's own `claude` CLI at every remaining SDK call site (`cortex_command/pipeline/dispatch.py`, `cortex_command/discovery.py`), dropping the SDK bundled-binary branch from `cortex_command/cli_resolver.py`; a missing `claude` fails loudly with "Cannot find claude — install Claude Code" and no fallback search. Alongside it, the install collapses to one shape: the dashboard stack moves into base `dependencies`, and `[all]` / `[dashboard]` / `[overnight]` survive as empty extra names so every existing install command — including the auto-installer's hardcoded `cortex-command[all] @ git+…@{CLI_PIN}` — keeps working, and the dashboard keeps working for operators with no Claude Code at all.

Tier: complex. Criticality: high.

## SDK Transport Protocol

Read against the installed SDK 0.2.153 (`.venv/lib/python3.14/site-packages/claude_agent_sdk/`).

**argv.** `SubprocessCLITransport._build_command()` (`_internal/transport/subprocess_cli.py:563-788`) always opens with `[cli_path, "--output-format", "stream-json", "--verbose"]` (:567) and always appends `--input-format stream-json` (:786). It never adds `-p`; a direct spawn must pass `-p` explicitly rather than rely on the CLI inferring print mode from non-TTY stdio. Option→flag mapping for the fields cortex sets is 1:1: `--system-prompt` (:569-582; `None` becomes an explicit `--system-prompt ""`, which suppresses the CLI default — cortex always passes a string), `--allowedTools` comma-joined (:596-601), `--max-turns` (:603, omitted when falsy), `--max-budget-usd` (:606, `is not None`), `--permission-mode` (:629), `--settings <path>` passthrough (:650-653, `_build_settings_value` :466-518), `--effort` (:770).

**Environment.** `connect()` (:806-864) inherits `os.environ` minus `CLAUDECODE`, sets `CLAUDE_CODE_ENTRYPOINT=sdk-py`, overlays `options.env`, force-sets `CLAUDE_AGENT_SDK_VERSION` last, and sets `PWD` when `cwd` is given. Cortex's own `_env` allowlist (`dispatch.py:682-701`) already clears `CLAUDECODE` itself, so a direct spawn reproduces this with `{**os.environ} - CLAUDECODE + _env` and no SDK-identifying vars.

**The handshake cortex does not need.** `SubprocessCLITransport.__init__` hardcodes `self._is_streaming = True` (:227-228) and `InternalClient._process_query_inner` (`_internal/client.py:140-142`) forces streaming mode even for a plain string prompt: it sends a control-protocol `initialize` request over stdin (`_internal/query.py:265-289`), waits for the matching `control_response` (60s default timeout), then writes the prompt as a `user` frame. For cortex — no hooks, no `can_use_tool`, no SDK-MCP servers, no agents or skills — that handshake carries `hooks: null` and nothing else. A direct spawn can pass the prompt positionally and never write stdin at all.

**Streams and errors.** Stdout and stderr are both line-framed across chunk boundaries (`_LineFramer`, :156-189); lines not starting with `{` are skipped (e.g. `[SandboxDebug]` noise, #347), a `{`-prefixed line that fails to parse raises `CLIJSONDecodeError`, and a single accumulated line above 1 MiB (`_DEFAULT_MAX_BUFFER_SIZE`, :36) raises. Stderr is piped only when a callback is set (:854) and a raise inside the callback is swallowed per line (:910-918). On stdout EOF the transport waits the process; a nonzero exit becomes `ProcessError` whose `.stderr` is the hardcoded placeholder `"Check stderr output for details"` (:1139-1145) — which is why `dispatch.py:1000-1003` already reads its own captured stderr instead. If the final `result` frame carried `is_error: true`, `Query._read_messages` (`_internal/query.py:411-437`) upgrades that to `ResultError` (`_errors.py:56-118`) carrying `subtype`, `errors`, `result`, `api_error_status`, `terminal_reason`.

**Event schema cortex reads** (`_internal/message_parser.py`): `assistant` (:151-224) → `message.content` blocks (`text`, `tool_use`) and `message.model`; `user` (:96-149) → `tool_result` blocks with `tool_use_id` / `is_error`; `result` (:308-341) → `subtype`, `duration_ms`, `is_error`, `num_turns`, `session_id`, and optional `stop_reason`, `total_cost_usd`, `result`, `errors`, `terminal_reason`. Unrecognized types hit `case _:` (:391-395) and are skipped — a direct parser can do the same.

**Live probe.** `claude -p --output-format stream-json --verbose --max-turns 1 "hi"` (run before the operator re-authenticated) emitted SessionStart `hook_started`/`hook_response` events, a `system`/`init` block, an `assistant` message with `"model": "<synthetic>"`, then a `result` frame with `is_error: true`, `subtype: "success"`, `terminal_reason: "api_error"`, exit 1, empty stderr. **`is_error: true` coexisting with `subtype: "success"` is the load-bearing detail**: failure detection must key on `is_error`. `error_max_budget_usd` is documented (`types.py:2049-2050`) but was not observed live.

## Web

**Headless mode is first-party supported.** The Agent SDK overview states that to drive the same agent loop from another language you run the CLI as a subprocess with `-p` and a JSON output format — this plan is the documented integration path, not a workaround. `--output-format stream-json` requires `--verbose`; `--include-partial-messages` adds token deltas. Under `-p` the starting permission mode is manual unless passed explicitly. Piped stdin is capped at 10 MB. Exit codes are 0/1, and **SIGTERM mid-turn loses the in-flight turn and exits 143** — SIGINT ends a turn cleanly.

**The event schema is deliberately unversioned.** Anthropic's documented mitigation is feature detection via the `system/init` `capabilities: string[]` array plus tolerance for unknown fields and values, with per-field "Requires Claude Code vX.Y.Z" notes rather than a stable-contract guarantee. Behavior has shifted release to release (exit-drain timeout changed at 2.1.214; `capabilities` itself needs 2.1.205+).

**The yank is a policy, not an incident.** Per the maintainers' PyPI support thread, old releases are being yanked with a dated notice and then deleted, oldest first, to stay under the storage quota; PyPI currently shows 30+ yanked versions from 0.0.23 through 0.2.99, all carrying the same 2026-09-19 deletion notice. Every wheel has bundled the `claude` binary since 0.1.8, ~82–94 MiB each, and there is **no packaging escape hatch** — no extra, no sdist-only path, no env var that yields a binary-free install; the documented way to use a system CLI is `cli_path=` at runtime, after downloading the binary anyway. So an exact pin is a recurring fuse and a range still pays the download.

**Prior art.** Independent Python (`claudestream`), Rust (`claude-wrapper`, `claude-code-rs`), and Go (`claudecli-go`, `claude-code-go`, `agent-wrapper`) projects already drive `claude -p --output-format stream-json` directly. Documented pitfalls from those and from write-ups: **errors land on stdout as a well-formed envelope with `is_error: true` while the process exits 1** (one project silently failed for three days by watching stderr only); partial lines across read chunks are the classic bug; auth, rate-limit, billing and model-not-found failures all surface as fields inside the JSON rather than distinct exit codes; free-text fields such as model names drift, so match structured fields only.

**Alternatives weighed.** (a) Keep the SDK on a range — does not address the rolling deletion policy and still pays ~90 MB per platform for a parser cortex does not need. (b) Vendor the SDK's parser types — MIT-licensed and legally clean, but means hand-syncing a daily-release package's dataclasses forever. (c) Install from sdist to dodge the binary — not offered as a packaging option. (d) Hand-rolled minimal NDJSON parser — matches prior art, is first-party sanctioned, and removes the failure mode entirely. **Recommendation: (d)**, scoped defensively: line-buffered reader, `is_error`-first error handling, `capabilities`-based feature detection rather than version-string comparison, and unknown `type`/`subtype` values treated as forward-compatible no-ops.

## Adversarial

Findings are verified against HEAD, the installed SDK, the recorded orchestrator stdout corpus, and a live `claude` 2.1.273 probe. Strongest first.

**1. The 64 KiB readline default is the highest-probability defect, and it is not protocol-level.** `asyncio.create_subprocess_exec` carries `limit=65536`; the first NDJSON line above that raises `ValueError: Separator is not found, and chunk exceed the limit` *mid-stream*, after the agent has done the work, landing in dispatch.py's bare `except Exception` as `unknown` → recovery `retry` → the same oversized frame recurs until the budget burns. The largest real line in this repo's own recorded orchestrator stdout is **41,412 bytes** (63% of the limit); one `Read` of a large file clears it. The SDK does not have this bug — it frames stdout itself at 1 MiB (`subprocess_cli.py:36`, enforced :930, :1095).

**2. `classify_error` is anchored on SDK exception types, and the plan does not replace that anchor.** The whole keyword-scan pass is gated behind `isinstance(error, ProcessError)` (dispatch.py:515), and `CLIConnectionError` → `infrastructure_failure` → `pause_human` (:512, ERROR_RECOVERY:332). After removal a failed spawn raises `FileNotFoundError` / `PermissionError` / `OSError`, none of which is `ProcessError`, so `agent_refusal`→pause_human, `effort_unsupported`→clamp_effort and `api_rate_limit`→pause_session all become unreachable, and an unspawnable `claude` degrades from "pause and wake the human" to "unknown → retry" — the runner silently retries a binary that cannot start, for every feature in the round. Note `CLINotFoundError` (subprocess_cli.py:314) is what routes this correctly today and cortex never names it; it is caught only through its base class.

**3. `env=_env` passed straight to `Popen` strips the child's world.** Both call sites build `_env` as a 2–5 key *overlay*; the SDK merges it onto `os.environ` minus `CLAUDECODE` (subprocess_cli.py:812-819). A direct `Popen(..., env=_env)` — the natural reading — hands the child no `PATH`, `HOME` or `SHELL`, so `claude` cannot resolve `git`/`bash` for tool calls or find `~/.claude` credentials, and it fails looking like an auth problem. Worse, `CLAUDECODE: ""` is a *deletion by overwrite* that silently becomes a no-op against a clean env dict.

**4. Do not delete `_SYSTEM_FALLBACKS` along with the bundled branch — they are different fallbacks.** `cli_resolver.py:44-48` searches `~/.local/bin/claude`, `/usr/local/bin/claude`, `~/.claude/local/claude`, and this repo's own hook text already documents the failure it covers: a Dock/Finder-launched session gets launchd's minimal PATH. The operator's `claude` is at `~/.local/bin/claude`, which is not on that PATH. Deleting the search turns "Claude Code is installed and working" into a hard "install Claude Code" refusal. The bundled-SDK branch is the one to delete.

**5. Piping both streams and draining them sequentially deadlocks.** Dispatch needs stdout incrementally *and* stderr live (the `--effort` warn-ignore detector and the hard-reject signature). `_spawn_orchestrator` dodges this by writing stdout to a file and setting `stderr=DEVNULL` — neither option is open to dispatch, so its shape is not reusable here. The SDK runs a detached concurrent stderr reader (:869-876); the replacement must too, or ~64 KB on the unread pipe hangs the run.

**6. There is no timeout or cancellation to port — but there is orphan prevention.** No `wait_for` / `asyncio.timeout` / `move_on_after` exists anywhere in `cortex_command/pipeline/`, so the `asyncio.TimeoutError` arm of `classify_error` is dead code. What the SDK does provide is a module-level `_ACTIVE_CHILDREN` set with an `atexit` SIGTERM reaper (:47-61) and a shielded close ladder (stdin EOF → wait 5s → terminate → wait → kill → wait, :945-1040). Both are lost. The runner's SIGTERM handler restores prior handlers and re-raises the signal (runner.py:1052-1136), so the process dies by signal and `atexit` never runs — leaving only the psutil descendant walk (:191-275), which swallows every psutil exception.

**7. `start_new_session` is a real fork the plan does not make.** `_spawn_orchestrator` passes it; the SDK does not. Adding it stops a terminal SIGINT from reaching the child, puts the child outside `os.killpg`'s reach in the runner's kill path, and leaves an `atexit` reaper with no pgid to target. Omitting it preserves today's behavior. Either is defensible; copy-paste will decide it otherwise.

**8. `--max-turns` is not in `claude --help` on 2.1.273** (`grep -c max-turns` → 0), though the CLI accepts it — an unknown flag exits 1 with `error: unknown option`. Cortex's turn-limit contract (the flag plus `stop_reason` / `num_turns` field names) would rest on an undocumented, unpinned surface, replacing a dependency that at least pinned a range and was smoke-tested per bump. Misclassifying `turn_limit_exhausted` is not hypothetical: dispatch.py:339-345 records an incident where it "reverts an already-merged feature."

**9. Frames arrive *after* the `result` frame.** Live order: `hook_started` ×2 → `init` → `assistant` → `rate_limit_event` → `post_turn_summary` → **`result`** → `hook_response`. A parser that breaks at `result` and abandons the pipe can hand the child EPIPE (nonzero exit → misclassification). Also, the result frame's first key is `duration_api_ms`, not `type`, so any `startswith('{"type":"result"')` fast path never matches. The runner's `_select_orchestrator_result_envelope` is the correct precedent: parse every line, take the last `type == "result"`.

**10. "Key on `is_error`" restates an existing mislabel rather than fixing it.** dispatch.py:898-903 turns *any* `is_error` into `budget_exhausted` → `pause_session`. So the live auth failure (`is_error: true`, `subtype: "success"`) pauses a whole overnight session reporting a budget problem for a credentials problem. The rewrite is when this is cheap to fix, and the result frame carries `terminal_reason`, `api_error_status` and `errors[]` to do it — the SDK prefers exactly those over subtype (`_internal/query.py:55-73`).

**11. A "lose nothing" parser poisons the error-classification corpus.** Only `TextBlock.text` reaches `output_parts` today (:876-878), and `output_parts` is the keyword corpus `classify_error` scans. The `system/init` frame carries `cwd` (the worktree path, which contains the feature slug), every installed skill and slash-command name, and the tool list — so a feature slug like `fix-failing-tests` would put "failing test" in the corpus (`_TEST_FAILURE_PATTERNS`, :352-366) and any failure would self-classify as `agent_test_failure`. The SDK made this impossible by construction; the new parser must keep the discipline explicitly.

**12. Unknown frame types must skip, not raise — and one of them is an upgrade.** The SDK skips unrecognized top-level types with a debug log but raises `MessageParseError` on a non-dict or type-less line (`message_parser.py:64, :93, :394`). The surface is already churning: the live run emitted `rate_limit_event` and `system/post_turn_summary`, neither in the schema cortex was written against. `rate_limit_event` carries structured `utilization` / `resetsAt` (observed `seven_day: 0.86`, `status: allowed_warning`) — a strictly better `api_rate_limit` signal than today's substring scan.

**13. The `[SandboxDebug]` non-JSON line is unobserved in this corpus.** `grep -c -v '^{'` over every recorded orchestrator stdout returns 0, and the live run produced none. Keep the skip rule — it is free — but do not cite it as observed behavior here.

**14. `--bare` would break cortex outright.** It skips hooks, CLAUDE.md discovery, plugin sync and auto-memory, all four of which dispatches depend on (including the tool-failure-tracker hook that consumes the `LIFECYCLE_SESSION_ID` dispatch injects), and it forces API-key auth while the runner authenticates by subscription OAuth (`apiKeySource: "none"` in the live init frame). If it becomes the `-p` default as the docs suggest, cortex needs an opt-out that does not exist yet — that is a risk to track, not a convenience to adopt.

**15. The extras scaffolding is cosmetic, and "`[all]` keeps working" is true by vacuity.** Verified in a probe build: hatchling emits `Provides-Extra` for an empty list, and uv on a *missing* extra only prints `warning: … does not have an extra named …` and installs successfully — so dropping the names costs one warning line, not a broken install. Two residues: the probe emitted **no `Requires-Dist` at all** for `all = ["probe[dashboard,overnight]"]` (harmless while the targets are empty, but re-verify against the real build), and eight in-repo sites assert that `[all]` is what supplies "the Claude Agent SDK the runner needs" — those become actively false instructions (`install.sh:62`, `CHANGELOG.md:29`, `CLAUDE.md:5`, `pyproject.toml:9-13`, `plugins/cortex-core/install_core.py:378`, `plugins/cortex-overnight/server.py:197,495,1449`).

**16. No proposed test would have caught the breakage that motivates this change, and the change deletes the last test touching anything real.** The 2026-09-16 failure was a PyPI-side yank — an install-time event no fixture, fake binary or spawn seam can see; only a scheduled fresh-install smoke test can. After removal the risk shifts to CLI flag/frame churn, which a fake `claude` and a recorded fixture also cannot see: they encode the implementer's belief about the CLI and rot into a green test asserting last quarter's schema. `test_sdk_settings_param_accepts_filepath` — which deliberately pops the stub to import the real SDK — dies with the dependency. A real-CLI smoke test is the only thing that closes the gap, and it is not free: one four-token live probe billed **$0.274**, because 27,422 cache-creation tokens of plugins/skills/CLAUDE.md load on every spawn.

**17. Two collateral sites are missing from the inventory.** (a) `sandbox_preflight.py:47` watches `pyproject.toml` for the literal `claude-agent-sdk`; because `_staged_diff_hunks` scans only *added* lines, the gate will not even fire on the commit that removes the line — pyproject drops out of sandbox-source enforcement silently rather than loudly. (b) `review_dispatch.py` and `lifecycle/review_brief.py` duplicate a parser solely to avoid a transitive SDK import; that reason evaporates, and leaving the duplication is a deletion-bias miss.

**18. `bypassPermissions` + a restrictive `--settings` + a positional prompt is an untested combination.** The SDK always runs `--input-format stream-json` with an `initialize` handshake, which makes it an "SDK host" in the CLI's own terms; `--permission-prompts` is documented as `"host" (the SDK host or --permission-prompt-tool) or "none"`. A positional-prompt spawn that never writes stdin is not a host, so a permission decision forced by the sandbox settings has no answerer. The live probe confirmed `permissionMode: bypassPermissions` — but with no restrictive settings file and no tool that could prompt. Preflight the real combination (bypassPermissions + per-dispatch `denyWrite`/`allowWrite` + real Edit/Write attempts + `failIfUnavailable`, nested inside the orchestrator's own Seatbelt) before committing to the positional shape.

**19. A positional prompt has thin margin and no guard.** `getconf ARG_MAX` is 1,048,576 and argv+env share it; `discovery._run_brief_query` passes an entire `research.md` as the prompt (largest in the corpus: 56,031 bytes) plus a large rubric as a second entry. Nothing bounds research.md — it is agent-generated — so this is an `E2BIG` at spawn time, an `OSError`, which under finding 2 classifies as `unknown` → retry forever. Secondary: the prompt is world-readable in `ps` for the life of the dispatch. Credentials are safe (both call sites pass tokens in env, not argv), but prompts are agent-written text cortex does not control.

**20. `discovery._run_brief_query` is thin because it is unguarded, not because it is simple.** No try/except around the loop, no stderr capture, no settings tempfile. Under the SDK a nonzero exit at least raised a typed `ProcessError`. With a direct spawn, a child that dies before any assistant frame yields an empty `output_parts`, which validates as an empty brief and falls through to the designed dense-path fallback — so a hard CLI failure becomes indistinguishable from a bad generation, and cortex never learns its brief sub-dispatch stopped working.

**Framing.** Removing the dependency genuinely eliminates the supply-chain class that broke every install. It trades a pinned, range-tested contract for an unversioned CLI surface on which cortex's central flag is not even documented — so the replacement's value depends on the defensive details above, not on the deletion alone.

## Open Questions

1. **Does `pipeline/conflict.py` hold a third `query()` call site?** `docs/internals/sdk.md:132` says so; the reference sweep found only `dispatch.py:850` and `discovery.py:677`. Answer by reading the file at implementation time — a missed call site is a runtime `ImportError` once the dependency is gone.
2. **Positional prompt or stdin?** Adversarial 19 gives a concrete `E2BIG` path (an unbounded agent-written `research.md` on argv) plus `ps` exposure, and Adversarial 18 raises a permission-answerer question for a spawn that never writes stdin. `claude -p` reads a prompt from stdin (capped at 10 MB, and cortex's largest is 56 KB), which sidesteps both. **Deferred to Spec**, which must pick one shape and state why; the live probe already ran the positional shape successfully, so this is a design choice, not a feasibility question.
3. **How is budget exhaustion actually surfaced?** `--max-budget-usd` is documented to end the run with an `error_max_budget_usd` subtype, but it was not observed live, and today's branch turns *any* `is_error` into `budget_exhausted` (Adversarial 10). Settle with a deliberate tiny-budget run before trusting the mapping, and decide there whether the mislabel is fixed in this change or explicitly left.
4. **Which test double, and what covers the real gap?** The injected-seam and fake-`claude`-script options trade ~93 tests' churn against fidelity, and neither sees CLI drift (Adversarial 16). Spec decides the unit-test seam *and* whether to add a `--run-slow` live smoke test (~$0.27 per run) and/or a scheduled fresh-install resolve check, which is the only thing that would have caught the yank.
5. **Does ADR-0014 get superseded or amended, and does the install-shape change earn its own ADR?** ADR-0014's bundled-vs-system premise disappears, but its effort-by-outcome half stays load-bearing, and its `_SYSTEM_FALLBACKS` search must survive (Adversarial 4). No ADR governs the extras shape today.
6. **Does the sandbox-source gate keep covering `pyproject.toml`?** Removing the watched literal makes the pattern dead, and the gate cannot fire on the removal commit itself (Adversarial 17a). Spec decides whether to retarget the pattern or accept the loss with a named reason.
