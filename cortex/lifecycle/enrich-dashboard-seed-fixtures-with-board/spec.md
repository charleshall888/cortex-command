# Specification: enrich-dashboard-seed-fixtures-with-board

> Epic reference: `cortex/research/dashboard-command-station/research.md` (parent #410) — background only, scoped to this ticket. Ticket-level research: `cortex/lifecycle/enrich-dashboard-seed-fixtures-with-board/research.md`.

## Problem Statement

The dashboard's five seed fixtures carry one-line bodies and none of the frontmatter the command-station views read, so #412's board and #413's reader have zero fixture coverage of epics, blockers, deferrals, lifecycle artifacts, or rendered markdown. Enriching them to ~14 items exposes a larger problem underneath: `cortex-dashboard-seed` is a shipped console script (`pyproject.toml:75`) that writes fixtures into the operator's **real** repository. It clobbers canonical live paths, destroys the overnight-state symlink `overnight/plan.py:588-592` maintains, installs a fake `executing` session the launchd guardian treats as a recovery target, and has already leaked seed output into this repo's git history (`0040d55c` untracked five seeded backlog items by hand). Its ID reservation is also a permanent allocator ceiling: because 990–999 are excluded from `max(ids)` but not from assignment, `_get_next_id` returns `990` forever once a real backlog reaches 989 — reproduced empirically, and dated to roughly early-2027 for this repo. Containing the seeder to an isolated root addresses all of it and makes the reservation deletable rather than replaceable. **Scope note, stated rather than implied**: 11 of this spec's 20 requirements address that underlying problem rather than the fixture variety the ticket was filed for. That weighting is the consequence of a deliberate scope decision recorded in Open Decisions, not an accident of drafting.

**#411 landed mid-refine.** `cortex_command/dashboard/ticket_feed.py` (`build_backlog_snapshot`) and its poller wiring (`poller.py:54,415`) are on disk as of 2026-07-27, though #411's ticket remains `in_progress`. Requirements below verify against that real snapshot builder rather than against the producer helpers, because the fields this ticket exists to give fixture coverage — `phase`, `deferred_status`, `deferred_tag`, and `blocked_why`'s kind/title joins — are computed only there (`ticket_feed.py:107-155,213-219`) and appear nowhere in `collect_items`.

## Phases

- **Phase 1: Fixture root containment** — the seeder writes to a per-user fixture root by default; no writer resolves the project root on its own; viewing is dashboard-scoped, not environment-scoped. Prerequisite for every later phase.
- **Phase 2: Allocator correctness** — delete the reservation, handle the corpora it already contaminated, and make allocation see the whole corpus.
- **Phase 3: Fixture enrichment** — the coverage matrix, now safe to grow because fixtures no longer land in a real backlog.
- **Phase 4: Record cleanup and docs** — untrack the stranded pure-seed artifact; realign the recipes and docs with the new invocation.

## Requirements

1. **A per-user fixture root replaces the project root as the seeder's default target**: a helper returns `${XDG_STATE_HOME:-$HOME/.local/state}/cortex-command/dashboard-seed/`, resolved fresh on each call so tests can redirect `XDG_STATE_HOME` — mirroring `cortex_command/init/install_state.py:24-31` verbatim in shape. A `--root PATH` flag overrides it. Acceptance: `cortex-dashboard-seed --help` lists `--root`; after `cortex-dashboard-seed` with no arguments in a clean checkout, `git status --porcelain cortex/` is empty. **Phase**: Fixture root containment

2. **Viewing the fixtures is dashboard-scoped, never environment-scoped**: `cortex dashboard` gains its own `--root PATH` flag which sets `CORTEX_REPO_ROOT` **in-process** before `uvicorn.run(...)`, exactly as `cli.py:493-496` already sets `DASHBOARD_PORT` in-process for its own consumers. The operator is never instructed to export or inline-prefix `CORTEX_REPO_ROOT`, because that variable is the unvalidated root funnel for 43 non-test modules (`common.py:87-89` returns it with no existence or marker check), and a seeded fixture root satisfies both it and `overnight/cli_handler.py`'s independent `_is_valid_repo_root` — so any persistence beyond one command silently redirects backlog creation, lifecycle verbs, and overnight writes into the throwaway tree. The seeder prints the `cortex dashboard --root <resolved root>` line. Acceptance: `cortex dashboard --help` lists `--root`; the seeder's stdout contains a line matching `cortex dashboard --root <resolved root>` and contains **no** `CORTEX_REPO_ROOT=` assignment (`cortex-dashboard-seed | grep -c 'CORTEX_REPO_ROOT='` = 0); and with a server started from exactly that printed line, `curl -s http://localhost:$DASHBOARD_PORT/partials/feature-cards` returns HTML containing `feature-seed-feature-alpha`. **Phase**: Fixture root containment

3. **No writer resolves the project root on its own**: `write_overnight_state` and `write_overnight_events` currently call `_resolve_user_project_root()` internally for their canonical copies (`seed.py:181`, `:282`), so `write_all(tmp_path, …)` writes session files under `tmp_path` while clobbering canonical files in the developer's real repo. Both take an explicit root. Acceptance: `grep -c "_resolve_user_project_root" cortex_command/dashboard/seed.py` = 1 (the CLI entry only), and a test asserts `write_all(tmp_path, sid)` creates no path outside `tmp_path`. This requirement is what unblocks testing `seed.py` at all. **Phase**: Fixture root containment

4. **`--clean` is scoped to the same resolved root and never deletes a git-tracked file**: today steps 5–7 unlink `pipeline-state.json`, `pipeline-events.log`, and `metrics.json` unconditionally (`seed.py:1206-1219`), so `--clean` on a never-seeded repo deletes tracked files. Acceptance: in this repo, with tracked `cortex/lifecycle/pipeline-state.json` present, `cortex-dashboard-seed --clean` at the default root leaves `git status --porcelain` empty. **Phase**: Fixture root containment

5. **Writer/cleaner symmetry is asserted by a test, not by convention**: a seed-then-clean cycle at an isolated root returns the tree to its prior state. Acceptance: a test captures the recursive file listing of a fresh root before `write_all`, runs `write_all` then `clean_all`, and asserts the recursive listing afterwards equals the one captured before — leaving no orphaned directories (`exit-reports/`, `learnings/`, feature dirs, or the session dir, none of which `written_paths` records today). **Phase**: Fixture root containment

6. **The 990–999 reservation is deleted, not replaced**: containment removes its premise, and deletion bias puts the burden on keeping it. Acceptance: `grep -c "990" cortex_command/backlog/create_item.py` = 0; `tests/test_create_backlog_item.py::test_skips_seed_range_when_seeds_present` is replaced by a test asserting the allocator returns `990` for a corpus whose highest ID is 989, and `991` after that file exists. **Phase**: Allocator correctness

7. **Deleting the reservation does not silently jump a contaminated repo's ID sequence**: the exclusion is currently the only thing hiding stray `99[0-9]-seed-*.md` files from `max(ids)`, and that population is real — `0040d55c` ("Untrack dashboard seed backlog items") removed `990-seed-feature-alpha.md` through `994-seed-feature-epsilon.md` from this repo by hand, and any consumer who ran the shipped seeder and never `--clean`ed still carries them. Left unhandled, their next real ticket allocates `995` and the sequence never returns. The allocator ignores files matching the seed-fixture naming the pre-containment seeder produced, and `cortex-dashboard-seed --clean` gains a documented one-time sweep of a project-repo path for operators migrating off the old regime. Acceptance: with `cortex/backlog/229-foo.md` plus `990-seed-feature-alpha.md`…`994-seed-feature-epsilon.md` on disk, `_get_next_id` returns `230`, not `995`; and a documented command removes those five files from a project repo. **Phase**: Allocator correctness

8. **Allocation sees archived IDs**: `_get_next_id` globs `backlog_dir` non-recursively, so `cortex/backlog/archive/` is invisible and an archived ID can be reallocated to a new ticket. This is a defensive fix on its own merits — **not**, as an earlier draft claimed, something Phase 3 makes urgent: `seed.py` references `create_item`/`_get_next_id` zero times and writes every fixture with hardcoded IDs, and under Phase 1 no fixture reaches a project backlog at all. It is also a no-op in every repo sampled (`wild-light` archive max 007 vs main max 410; `gaggimate-barista` 022 vs 029). It becomes live the first time anyone archives a recently-created ticket, putting an archived ID above the main-directory max. Acceptance: with `cortex/backlog/010-y.md` and `cortex/backlog/archive/500-x.md` present, `_get_next_id` returns `501`. **Phase**: Allocator correctness

9. **Pipeline fixtures reference real seeded items**: `write_pipeline_fixtures` hardcodes `backlog_id` values `990`/`991`/`992` (`seed.py:313,319,325`) — a second, independent duplication of the band that references `create_item.py` not at all, and exactly the "second consumer" #231's spec said would justify a shared constant. Acceptance: every `backlog_id` in the generated `pipeline-state.json` matches an `id` in the generated backlog fixtures; no numeric literal in the 990–999 band remains in `seed.py`. **Phase**: Allocator correctness

10. **The fixture table carries optional frontmatter**: `_BACKLOG_ITEMS` is a fixed 6-tuple rendered by one hard-coded f-string emitting 8 of the 21 fields `collect_items` reads, so `parent`, `blocked-by`, `lifecycle_slug`, and `areas` require restructuring both. Fields are emitted when present and omitted when absent — never as empty scalars. Acceptance: `collect_items` over the seeded root returns records whose `parent`, `blocked_by`, `lifecycle_slug`, and `areas` are populated for the fixtures that declare them and empty for those that don't. Array fields use the inline `[a, b]` form required by `skills/backlog/references/schema.md:23`. **Phase**: Fixture enrichment

11. **Every state in #411's pinned snapshot schema has a fixture, verified against the snapshot itself**: epic-with-children; child pointing at a non-epic parent; `ineligible` kind `status`; all four blocker outcomes — internal-non-terminal, internal-terminal (resolves silently, still listed), external (`anthropics/claude-code#34243`), and `not_found` (a well-formed UUID matching no item); both backlog deferral forms; non-null `phase`; `archive_ids`. Acceptance: a test calls `build_backlog_snapshot` (`cortex_command/dashboard/ticket_feed.py`) over the seeded root and asserts each state on the returned snapshot — blocker outcomes via `snapshot["blocked_why"]["<id>"]` entries carrying the expected `kind` and `status`, **not** via `readiness.py` reason strings, because a terminal internal blocker returns `(True, None)` and is otherwise indistinguishable from a fixture declaring no blockers at all; deferral via `deferred_status`/`deferred_tag`; ineligibility via `snapshot["ineligible"]` entries carrying `kind: "status"`. **Phase**: Fixture enrichment

12. **One fixture deliberately carries an unresolvable artifact reference**: the corpus exercises the epic's named "dead placeholder links" defect today only by accident — no fixture sets `lifecycle_slug`, and `slugify("Seed: Add authentication to API gateway")` does not equal `seed-feature-alpha`, so every link already dangles. Fixing the linkage would silently delete the only coverage of the state epic #410 exists to fix. Acceptance: exactly one fixture declares a `spec:` or `lifecycle_slug:` path that does not exist on disk, and a comment in `seed.py` states why. **Phase**: Fixture enrichment

13. **The third deferral vocabulary is seeded**: backlog `status: deferred` and `tags: [deferred]` are backlog-frontmatter states, but the overnight run outcome `deferred` lives in `_FEATURES` (`seed.py:81-87`), which seeds only `merged, merged, running, paused, failed`. It has dedicated rendering (`app.py:91,104` `badge-amber`/`⚠`) that no fixture exercises. Acceptance: a sixth `_FEATURES` tuple with status `deferred` exists, and the generated `overnight-state.json` contains it. **Phase**: Fixture enrichment

14. **At least one fixture links to a lifecycle directory carrying reader-renderable artifacts**: `write_feature_files` writes only `agent-activity.jsonl`, `events.log`, and checkbox-only `plan.md` — no `research.md` or `spec.md`, which #413 renders. Acceptance: one fixture's `lifecycle_slug` resolves to a directory containing `research.md`, `spec.md`, and `plan.md`, and `build_backlog_snapshot` reports a non-null `phase` for that item — the `phase` key exists only on the snapshot (`ticket_feed.py:217`); `collect_items` emits `lifecycle_phase` and has no `phase` key at all. **Phase**: Fixture enrichment

15. **Fixtures self-identify without any feed-side filtering**: #411's approved spec forbids filtering; self-identification is a different mechanism, and no prior art ships commingled unmarked demo data. 16. **At least one fixture body exercises the full markdown pipeline**: `data.py:940-944` enables only `fenced_code` and `tables`. ## Non-Requirements

- **No seed-identity mechanism ships.** No manifest, no filename token, no tag-based allocator lookup, no high-offset band. Containment removes the premise; the research weighed all six candidates and each answers a question that no longer exists.
- **No feed-side filtering.** #411's "No seed filtering of any kind" stands untouched, and its pinned R3 snapshot schema is not altered by this ticket.
- **No refusal guard.** The Rails `ProtectedEnvironmentError` pattern was considered and declined: the isolated-root default already prevents the failure, so a guard would enter without independent named evidence (`project.md:41`).
- **No validation added to `_resolve_user_project_root`.** R2 removes this ticket's own reliance on `CORTEX_REPO_ROOT`; hardening the shared funnel against every other caller's misuse is a separate concern with its own blast radius.
- **Does not untrack `cortex/lifecycle/overnight-events.log`** — 31 of 32 lines are non-seed events.
- **Does not fix #411's pending R17 reconciliation** (its ticket still carries the original title and no `## Update` section) — that belongs to #411.
- **Does not fix `project.md:59`'s ADR-0029 citation**, which points at the sync-allowlist ADR rather than any lifecycle-identity ADR. Recorded in research; unrelated to this ticket.
- **No per-phase view tests for #412/#413.** This ticket ships fixture data and the R17 snapshot smoke test; each consuming ticket ships its own view tests, per the original charter.

## Edge Cases

- **`CORTEX_REPO_ROOT` left set in the operator's shell**: the variable is read unconditionally by 43 non-test modules with no existence or marker check (`common.py:87-89`), and a seeded fixture root satisfies `overnight/cli_handler.py`'s independent `_is_valid_repo_root` because it contains a bare `cortex/` directory — so backlog creation, lifecycle verbs, and overnight writes would all silently target the throwaway tree. R2's in-process `--root` flag is what keeps this out of the operator's environment; no instruction anywhere in this ticket's docs or output may tell an operator to export it.
- **Stale `99[0-9]-seed-*.md` files in a project repo from a pre-containment seed run**: covered by R7. Without it, deleting the reservation jumps the operator's real ID sequence past the stray files permanently.
- **Mixed-content event log with a seed first line**: `clean_all` step 2 gates on the first line containing `overnight-seed`, and in this repo that line *is* line 1 of a 32-line mostly-non-seed file — so today's `--clean` would delete 31 real events. Containment resolves it by construction (the cleaner never reaches the project repo), and R4's test pins that.
- **Overnight-state symlink**: `overnight/plan.py:588-592` maintains `cortex/lifecycle/overnight-state.json` as a single-active-session symlink; the seeder deliberately replaces it with a regular file and `clean_all` never restores it. Under containment the seeder must not touch the project path at all — asserted by R1's `git status` check.
- **Guardian recovery target**: a seeded session writes `"phase": "executing"` (`seed.py:166`) with no `runner.pid`, which `recovery.py:77-79` treats as needing recovery and `guardian.py:49-62` enumerates on a launchd timer. Fixtures under the isolated root are outside the guardian's `state_root`; no fixture may be written to a project-repo `sessions/` path.
- **`build_epic_map` schema strictness**: it raises `SchemaVersionError` when `schema_version != "1"` (`build_epic_map.py:126-133`). Fixtures pass today only because `_opt` strips the quotes from `schema_version: "1"`. The new epic fixture flows through this path — emit `schema_version: "1"` exactly.
- **`XDG_STATE_HOME` unset or unwritable**: fall back to `$HOME/.local/state` per the `install_state.py` precedent; an unwritable root fails loudly rather than silently falling back to the project repo.
- **Seeding twice without cleaning**: fixtures are deterministic, so a second run overwrites in place — no orphans, no ID drift.
- **A consumer repo with no `cortex/backlog/archive/`**: the archive fixture is created under the isolated root only; the seeder never `mkdir`s into a project tree.

- **MODIFIED** `cortex_command/cli.py` — `cortex dashboard` gains `--root`, set in-process.
- **MODIFIED** `cortex_command/backlog/create_item.py` — reservation deleted; stale seed-fixture files ignored; allocation includes `archive/`.
- **MODIFIED** `tests/test_create_backlog_item.py` — the reservation-pinning test is replaced.
- **MODIFIED** `docs/dashboard.md`, `justfile` — new `dashboard-demo` recipe, invocation, and rationale.
- **REMOVED from tracking** `cortex/lifecycle/pipeline-state.json`.
- **ADDED** a test module for `seed.py` (none exists today), including the R17 snapshot smoke test.
- **Behavioral break, stated plainly**: `just dashboard-seed` alone no longer populates the operator's own dashboard. `just dashboard-demo` is the replacement single command. Completing Phase 1 without Phase 3 leaves a value-negative window — the operator loses sight of even the five bare fixtures before the enriched ones land — which is why R19's recipe ships rather than leaving the two-command pair as the only path.

## Technical Constraints

- File-based state only (ADR-0001, accepted); no database, no external ID service.
- `cortex-dashboard-seed` ships to consumers via the `[dashboard]`/`[all]` extras — every behavior here reaches installs whose corpora are unlike this repo's.
- Neither `create_item.py` nor `dashboard/seed.py` is lifecycle-gated (`CLAUDE.md:28`).
- Frontmatter scalars route through `frontmatter_quote.py`'s allowlist (ADR-0027, proposed) if any new string-intended numeric-looking field is emitted.
- Canonical blocker spelling is hyphenated `blocked-by`; arrays inline (`skills/backlog/references/schema.md:17,23`).
- The dashboard remains read-only; nothing here adds a write to its read path (`observability.md:102,108`).
- `#411`'s `build_backlog_snapshot` is on disk but its ticket is `in_progress`; requirements verify against the pinned R3 schema, which #411's spec fixes as the deliverable, so a late change to #411's internals surfaces as an R17 failure rather than silently.

None outstanding. Resolved at refine time: seeding contained to an isolated root (operator, 2026-07-27); containment delivered as a seeder default rather than documentation (operator); stranded artifact cleanup limited to `pipeline-state.json` (operator); identity mechanism dropped entirely as containment removes its premise (research). **Scope kept whole against a recorded dissent**: the research phase's adversarial pass argued for splitting this into three tickets — allocator correctness, seed containment, fixture enrichment — on the mechanical ground that `seed.py` cannot be tested until the root divergence is fixed, and on the blast-radius asymmetry of allocator changes riding a ticket typed `chore`. ## Proposed ADR

### Proposed ADR: 0030-dashboard-seed-fixtures-are-contained-to-an-isolated-root

`cortex-dashboard-seed` was built to populate the operator's real repository so fixtures appear in their real dashboard alongside real work (`seed.py:4`). That purpose is the direct cause of every defect research found: it clobbers canonical live paths, destroys the single-active-session symlink `overnight/plan.py` maintains, writes a fake `executing` session that the launchd guardian treats as an unattended recovery target, has already leaked seed output into git history, and forced a numeric ID reservation whose exclusion predicate is a permanent allocator ceiling. **Decision**: the seeder writes to a per-user fixture root (`${XDG_STATE_HOME:-$HOME/.local/state}/cortex-command/dashboard-seed/`) by default, and the dashboard renders it via its own `--root` flag which sets the root in-process. The ID reservation is deleted rather than replaced, because containment removes the collision it guarded against. **Trade-offs, all three**: (1) fixtures no longer appear beside real work in the operator's own dashboard, and viewing them costs a distinct command — mitigated by a combined `just dashboard-demo` recipe, but a real loss. (2) The obvious cheap implementation — telling the operator to set `CORTEX_REPO_ROOT` — was rejected despite requiring no code, because that variable is the unvalidated root funnel for 43 non-test modules and a fixture root satisfies every marker check that guards it; a dashboard-local flag costs a small code change and confines the redirect to one process. (3) Containment is forward-looking only: repos already contaminated by the pre-containment seeder need the R7 migration path, since deleting the reservation stops hiding the stray IDs it was masking. Accepted because the alternative is a shipped console script that writes unreviewed state into every consumer's repository, and because #231 already deferred this same structural fix ("Fix B") with the trigger "if dashboard-seed grows beyond test scaffolding", which this ticket is.
