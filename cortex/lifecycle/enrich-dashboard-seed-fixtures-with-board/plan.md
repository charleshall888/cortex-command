# Plan: enrich-dashboard-seed-fixtures-with-board

## Overview

Contain `cortex-dashboard-seed` to a per-user fixture root before growing the corpus: every writer takes an explicit root, the cleaner derives its removals from the same tables the writers use, and the dashboard reaches the fixtures through its own in-process `--root` flag. With fixtures out of every real backlog, the 990–999 reservation is deleted (not replaced) and the fixture table is restructured into optional-field records carrying the ~14-item coverage matrix. Phases 1 and 2 are independently reviewable; Phase 3 depends on Phase 1 only because `seed.py` cannot be tested until the root divergence is fixed.

**Architectural Pattern**: shared-state (the resolved fixture root is the single value every writer, the cleaner, the CLI banner, and the dashboard flag agree on).

> No `learnings/recovery-log.md` exists for this feature — this is a first planning pass, not a recovery.

## Outline

### Phase 1: Fixture root containment (tasks: 1, 2, 3, 4, 5)
**Goal**: The seeder's default target is `${XDG_STATE_HOME:-$HOME/.local/state}/cortex-command/dashboard-seed/`, no writer resolves a root on its own, the cleaner is symmetric with the writers, and the dashboard renders the fixture root via `cortex dashboard --root`.
**Checkpoint**: `cortex-dashboard-seed` and `cortex-dashboard-seed --clean` both leave `git status --porcelain cortex/` byte-identical to its pre-run value, and a test asserts `write_all(tmp_root, sid)` touches nothing outside `tmp_root`.

### Phase 2: Allocator correctness (tasks: 6, 7)
**Goal**: Delete the 990–999 reservation, ignore the stray fixture files it was masking, and make allocation see `cortex/backlog/archive/`.
**Checkpoint**: `_get_next_id` returns `990` for a corpus topping out at 989, `230` for a corpus contaminated by the five pre-containment fixture files, and `501` when an archived 500 outranks the active max.

### Phase 3: Fixture enrichment (tasks: 8, 9, 10)
**Goal**: Restructure `_BACKLOG_ITEMS` into optional-field records and grow the corpus to ~14 items covering every state in #411's pinned snapshot schema, plus the `deferred` run outcome and reader-renderable lifecycle artifacts.
**Checkpoint**: `build_backlog_snapshot` over the seeded root returns the pinned R3 key set with epics, all four blocker outcomes, both deferral forms, a non-null `phase`, and non-empty `archive_ids`.

### Phase 4: Record cleanup and docs (tasks: 11, 12, 13, 14)
**Goal**: Untrack the stranded pure-seed artifact, ship a single seed-and-serve recipe, and realign the docs and the ADR record with the new invocation.
**Checkpoint**: `git ls-files cortex/lifecycle/pipeline-state.json` is empty, `just dashboard-demo` exists and serves the fixture root, and `docs/dashboard.md` states the invocation, the containment rationale, and the seeded/unseeded regime split.

## Risks

- **The `.claude/` marker is an addition the spec does not name.** `app.py`'s lifespan hard-fails on a root without `.claude/`, so R2's live render is unreachable without it. The alternative — relaxing that check — touches the dashboard's own startup guard and has a wider blast radius; the marker directory is content-guarded so `--clean` can never take a real repo's `.claude/` with it.
- **The spec's proposed ADR number 0030 is already taken.** Plan allocates 0033. Worth a glance at approval time in case the operator wants the spec's ADR block amended.
- **`--print-root` is a flag beyond the spec's surface.** It exists so the `dashboard-demo` recipe has one source of truth for the XDG path instead of re-deriving it in shell. Dropping it means duplicating the path expression in `justfile` — a small, real drift risk either way.
- **Untracking `pipeline-state.json` needs a `.gitignore` entry, not just `git rm --cached`.** The spec's acceptance checks only `git ls-files`, but leaving the file untracked-and-visible would break R1's and R4's `git status --porcelain` checks. If the operator would rather delete the working-tree copy outright, that is a one-line change to Task 11 and loses only the fake pipeline panel.
- **Phase 3 is a six-task chain through one file.** `seed.py` is a hub and the Phase-1 rework is structural (writers re-signatured, cleaner rebuilt), so a registration seam cannot apply; the honest remedy is the serialized ordering above. Splitting the corpus into a new `seed_fixtures.py` module would widen the graph but adds a file the spec's Changes-to-Existing-Behavior does not list — declined for spec fidelity.
- **Behavioral break, as the spec states plainly**: `just dashboard-seed` alone no longer populates the operator's own dashboard. `just dashboard-demo` is the replacement single command, and it ships in the same change set so no value-negative window opens.
- **The legacy sweep deletes files from a real project repo.** It is opt-in behind an explicit flag, matches only the five filenames the pre-containment seeder produced, and skips anything git-tracked — but it is the one operation in this ticket that can still reach an operator's tree.
- **The recorded dissent stands**: the research phase argued for splitting this into three tickets, and the operator kept it whole (2026-07-27). Phase 2 is the one to review hardest on those terms — it is the only phase whose blast radius reaches every consumer's ID allocation.
