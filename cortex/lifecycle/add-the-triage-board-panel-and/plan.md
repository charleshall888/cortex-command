# Plan: add-the-triage-board-panel-and

## Overview

Add one read-only polled panel (`§ 11`, `/partials/triage-board`) that renders #411's shipped `backlog_snapshot` as epic-grouped disclosure rows plus a flat list, following the dashboard's existing six-seam panel recipe with no changes to the feed, the poller, or the shared badge maps. The board's data joins are the whole risk surface, so the fixture generator is built as its own artifact and the template's tests drive it through the real `build_backlog_snapshot` rather than a hand-written dict. Phase 2 corrects ticket #412's own falsified record and is independent of the code in either direction.

No recovery log exists for this feature — this is a first planning pass.

## Outline

### Phase 1: Triage board panel (tasks: 1, 2, 4, 5)
**Goal**: A polled `§ 11` panel that renders every active ticket with correct epic, readiness, blocker, and deferral joins, covered by tests that fail if the feed's shape changes.
**Checkpoint**: `pytest cortex_command/dashboard/tests/` passes with `/partials/triage-board` in `PARTIAL_ROUTES` and board template tests driven by `build_backlog_snapshot`.

### Phase 2: Ticket record reconciliation (tasks: 3)
**Goal**: #412's backlog record states what survived review, by appending rather than rewriting.
**Checkpoint**: The ticket carries an `## Update — reconciled at spec time (#412)` section naming five falsified claims plus the dropped strip, with the original prose byte-unchanged.

### Task 1: Author the triage board panel fragment
- **Files**: `cortex_command/dashboard/templates/triage_board.html`
- **What**: Create the panel fragment that renders `state.backlog_snapshot` as epic groups plus a flat list of rows, covering the never-polled, empty, and stale arms. This is the ticket's only new rendering surface.
- **Depends on**: none
- **Complexity**: complex
- **Context**: Fragment file, no `<section>` wrapper, no registration step — `app.py:58-76` resolves `templates/` by directory scan and `templates/` must never gain an `__init__.py`. Model the overall shape on `backlog_panel.html` (section label line, `<h2>` with a `phase-tag` count, `stream-line` doc line, arm-per-state `{% if %}`) and the row shape on `feature_cards.html:50-101` (`<details>` / `<summary>`, no anchor on the row).

  **Structure, top to bottom.** (a) `{% from "patterns/badge.html" import badge %}`. (b) `<span class="sec-num"><strong>§ 11</strong>triage</span>` as the partial's own first output line — the `base.html` placeholder is replaced on first `load` by `hx-swap="morph"`, so a single-site label disappears (R2). (c) `{% set snap = state.backlog_snapshot %}`. (d) `<h2>Triage <em>board</em> <span class="phase-tag">…</span></h2>`. (e) three arms: `snap is none` → `<p class="empty-state">loading triage board</p>`; `snap` with empty `snap['item_order']` → a distinct `<p class="empty-state">` line naming an empty corpus; populated → the board. (f) In the populated arm a `<div class="stream-line">` whose children are a `doc · …` span and a trailing `<span class="ml-auto">refresh · 30s</span>`, plus a visible staleness span rendered only when `snap['stale']` is true (`snap['polled_ts'] | format_elapsed` is the honest timestamp; `state.last_updated` is rewritten every 2s by a different loop and must not be used). All three arms emit the `§ 11` line (R14).

  **Jinja access trap — load-bearing.** `snap` is a `dict`, and Jinja's `foo.bar` tries `getattr` before `__getitem__`. `snap.items` therefore resolves to the bound `dict.items` **method**, not the snapshot's `items` key, and renders silently wrong. Use subscripts for every snapshot key: `snap['items']`, `snap['item_order']`, `snap['epics']`, `snap['ready']`, `snap['ineligible']`, `snap['blocked_why']`, `snap['stale']`, `snap['polled_ts']`. Same rule for per-item dicts on keys named `items`/`keys`/`values`/`get`/`update`/`copy`/`pop`.

  **Snapshot shape** (authoritative docstring: `cortex_command/dashboard/ticket_feed.py:13-55`). `items` is `str`-keyed, each value a `collect_items` record (`generate_index.py:186-209`: `id` (int), `title`, `status`, `priority`, `type`, `tags`, `blocked_by`, `parent`, `lifecycle_phase`, …) plus `deferred_status` (bool), `deferred_tag` (bool), `phase` (null-normalized). `item_order` is a `str` id list in priority-then-id order. `epics` is `build_epic_map`'s two-key envelope, so read the map at `snap['epics']['epics']` — iterating the outer dict yields the literal keys `schema_version` and `epics` and zero epic ids (R5). Each epic value is `{"children": [...]}` with **no title**; each child carries only `{id, spec, status, title}` with `id` as **int** (`build_epic_map.py:158-163`). `ineligible` is a **list** of `{id, reason, kind}`. `blocked_why` is a `str`-keyed map to entries `{ref, kind, status, title}` where `kind` ∈ `internal|external|not_found` and `title` is frequently `null`.

  **Joins.** Build two template-scope lookups before rendering, using the mutation idiom `backlog_panel.html:38-46` already establishes (`{% set _ = coll.append(...) %}` / `{% set _ = mapping.update({k: v}) %}`): `ineligible_by_id` from the `ineligible` list, and `child_ids` as a list of `child['id'] | string` across all epics. Stringify every child id before subscripting `snap['items']` — child ids are `int`, `items` keys are `str`, and an unconverted lookup yields a Jinja `Undefined` that renders blank instead of raising (R6). Resolve **every** per-row display field through `snap['items'][id]`, never from the child record, which has none of `priority`, `type`, `phase`, `deferred_status`, `deferred_tag` (R7). Rows read `phase`, not `lifecycle_phase` — the raw field still carries the live string `"none"` for some items (R7).

  **Row set.** Rows are `snap['item_order']`, not `ready` (R4). Epic groups render `<div class="epic-group">` + `<h3>` with the epic's title joined via `snap['items'].get(epic_key, {})` — a plain `.get` on the **string** key, never `int(epic_key)`, and never `triage.py:263-265`'s bare `except Exception`, which degrades the whole map to `{}` and is indistinguishable from "no epics". A non-numeric or absent epic key renders under its raw key with no title and leaves the rest of the board intact. An epic group with zero children renders an explicit "no active children" line, not an empty body and not a suppressed group (R15). The flat list below is every `item_order` id **not** in `child_ids`; epic items themselves are nobody's child and therefore land in the flat list — that is deliberate, and it is why the epic group header is an `<h3>`, not a row: exactly one `<details id="ticket-N">` per `item_order` id keeps DOM ids unique, which `base.html:2219-2257`'s `sessionStorage` restore requires. No count or length threshold selects between layouts (R8).

  **Rows.** Define a same-file `{% macro ticket_row(...) %}` and pass everything it needs as explicit arguments (record, id, ineligible entry, blocker list, ready flag, status class map) rather than relying on closure over template-level `{% set %}`. Each row is `<details class="…" id="ticket-{{ id }}">` with a `<summary>`; the id is ticket-derived, never index-derived, because `item_order` re-sorts on any priority or status change (R13). No row element carries `href`, `hx-get`, `hx-push-url`, or `onclick` — `/tickets/{id}` is #413, and `feature_cards.html:226-228`'s live `href="#"` placeholders are the defect epic #410 cites.

  **Badges and flags.** Define a template-local status→class dict mapping to the `badge-*` class names defined at `base.html:642-680` (`badge-green`, `badge-blue`, `badge-red`, `badge-amber`, `badge-gray`, `badge-purple`) and call `badge(css_class=…, label=…)`. Do **not** copy `backlog_panel.html:2-17`'s values — those are CSS custom properties consumed as `style="--c: …"` and would emit `class="badge var(--c-state-failed)"`, matching no rule. Do **not** call `badge(status=…)`: `_BADGE_CLASS_MAP` (`app.py:82-93`) is the feature/run-outcome vocabulary and has no `blocked` key. Map at minimum `backlog`/`open`/`proposed` → `badge-gray`, `refined`/`in-progress`/`in_progress` → `badge-blue`, `deferred`/`on-hold` → `badge-amber`, with an unrecognized-status fallback of `badge-gray`; `backlog` must **not** be amber (R12). Status, type, and priority all render verbatim with a fallback class — all three vocabularies are open in practice (R10). `deferred_tag` renders as a **non-badge** text flag (e.g. `<span class="phase-label">tag · deferred</span>`) so it can never be confused with the run-outcome `deferred` at `alerts.py:81`; `deferred_status` renders as the status badge (R12). Blocked is derived, not a status: a row is blocked iff its id appears in `ineligible_by_id` with `kind == "blocker"` — never from truthy `blocked_by`, which `triage.py:96-97` uses and which over-badges items whose only blockers are terminal. A blocked row renders `badge(css_class='badge-red', label='blocked')` plus its `blocked_why` entries as plain text `#<ref> (<status>)`, falling back to the entry's `kind` when `status` is null (R11). Ineligible rows of any kind display their `reason` string (R4). Ready rows carry a plain non-badge ready marker.

  **Design system.** Use existing token classes only — `empty-state`, `stream-line`, `ml-auto`, `phase-label`, `phase-tag`, `sec-num`, `num`, `badge-*`. No raw hex, no `bg-gray-*`/`text-gray-*`, no `px` values inside `style` attributes (`DESIGN.md:58-68`). Add no new CSS.

## Risks

- **An epic item renders as a flat-list row while its group header is an `<h3>`.** R8 defines the flat list as every `item_order` id that is not any epic's child, which includes epic items themselves. Rendering the group header as a row instead would emit `id="ticket-N"` twice for the same epic, producing duplicate DOM ids and breaking `base.html:2219-2257`'s `sessionStorage` restore, so the plan keeps headers non-row. The visible consequence is that an epic appears once as a heading and once as a row; if that reads wrong in the browser, the fix is a rendering-only change.
- **Board tests do not block CI.** Only `test_routes_smoke.py` runs in `.github/workflows/validate.yml`, it asserts HTTP 200 only, and its fixture skips the lifespan — so CI exercises the never-polled arm alone. Everything Task 5 adds runs only under `just test`'s `tests-dashboard` (`justfile:571`), which no GitHub workflow invokes. Wiring that gap is deliberately out of scope (spec Non-Requirements; adjacent to #415).
- **The 30s cadence diverges from `observability.md`'s "dashboard total refresh ≤ 7s."** `backlog_panel.html` already diverges; this is an unrecorded requirements conflict named as input to #415, not resolved here.
- **A second status vocabulary now exists in template space.** `backlog_panel.html:2-17` maps backlog statuses to CSS custom properties; the board maps the same statuses to `badge-*` class names. Two maps for one vocabulary can drift. Merging them is not possible without changing the shared `badge()` macro or the aggregate bar's `.tint-c` mechanism, both fenced off by the spec.
- **The board and `/cortex-core:dev` will disagree**, deliberately, on tag-deferred readiness and on data source (`triage.py` reads gitignored `index.json`; the feed reads raw `.md`). Documented in the spec's Changes to Existing Behavior; no reconciliation is attempted.
