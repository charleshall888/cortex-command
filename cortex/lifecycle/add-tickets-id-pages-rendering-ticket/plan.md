# Plan: add-tickets-id-pages-rendering-ticket

## Overview

Add a deep-linkable `/tickets/{id}` reading page and a per-artifact HTMX partial, on top of a repaired markdown path that stops silently deleting `<slug>`-style placeholders. Three architectural decisions carry the work: the sanitizer literalizes *attribute-free* unrecognized tags only (so the shipped hostile-HTML assertions stay true), artifact discovery is a two-key join resolved per request with no caching, and both new handlers are plain `def` so Starlette runs them off the event loop.

**Architectural Pattern**: layered

## Outline

### Phase 1: Lossless rendering (tasks: 1)
**Goal**: The shipped markdown path preserves placeholder tokens instead of dropping them.
**Checkpoint**: `cortex/lifecycle/<slug>/research.md` renders with an escaped `<slug>` token, every existing `TestLoadTicketBody` assertion still passes, and the ten largest real artifacts render with zero double-escaping.

### Phase 2: The ticket page (tasks: 2 [badge pattern], 5, 6)
**Goal**: A `/tickets/{id}` page rendering badges, body, linkified epic children, and lazily-fetched artifacts.
**Checkpoint**: `GET /tickets/{seeded id}` → 200 with one `hx-get` per present artifact and no artifact prose in the page body; `GET /tickets/999999` → 404; both routes stand down under a non-local backend; `pytest cortex_command/dashboard/tests/` exits 0.

### Phase 3: Inbound links (tasks: 2 [board link-out], 3, 4)
**Goal**: The dead placeholder links and the seed defect that would mask them are retired, and the board connects to the page.
**Checkpoint**: Every seeded feature card's backlog link resolves under the seed corpus, and a rendered board row's expanded area carries an `href="/tickets/{id}"` link-out to its ticket page.

Re-emit such a token as escaped literal text instead, so 5% of artifacts and 1.1% of ticket bodies stop losing content.
- **Depends on**: none
- **Complexity**: simple
- **Context**: `data.py:1236-1304` (`_TicketBodySanitizer`), `data.py:1216-1234` (`_TICKET_ALLOWED_TAGS`, `_TICKET_VOID_CONTENT_TAGS`, `_TICKET_ALLOWED_ATTRS`). The literalization rule is **attribute-free unrecognized start tags only**, and never a void-content tag: `handle_starttag` emits `escape(self.get_starttag_text())` when `tag not in _TICKET_ALLOWED_TAGS`, `tag not in _TICKET_VOID_CONTENT_TAGS`, `not attrs`, and `not self._suppress_depth`; `handle_endtag` mirrors it for the same tag names (`</slug>`); everything else keeps today's drop-and-unwrap behavior. New tests go in `TestLoadTicketBody` (`tests/test_data.py:1586`), one method per case, following that class's `_corpus(tmp)` fixture idiom: a bare `<slug>` in prose asserted to appear escaped in `got["html"]`, and the same token inside a fenced block asserted to still render through the code path without double-escaping (`&amp;lt;` absent).

## Risks

- **The sanitizer's literalization rule is narrower than "reconstruct unrecognized tags".** Attribute-free only, because `test_raw_html_in_a_body_is_stripped_not_executed` asserts `onerror`/`onclick` never appear in output and both ride attributed tags; echoing those as escaped text would be safe but would fail requirement 2's "existing tests pass unchanged". The alternative — an HTML-element-name registry, literalizing `<slug>` but not a bare `<div>` — is more precise and more to maintain, and on the measured corpus (dropped tokens: `path`, `url`, `slug`, `ts`, `topic`, `line`, `repo`, `id`) the two rules behave identically. Bare block HTML in a body now shows as literal text rather than vanishing; that is the point of the fix, but it is a visible change to #412's shipped reader.
- **A concurrent session has uncommitted work in three of these files.** `seed.py`, `tests/test_seed.py`, `tests/test_templates.py` and `ticket_feed.py` carry in-flight #458 edits (a closed epic with a live child, seeded ids 15-16). Task 3 must append after whatever the highest `_BACKLOG_ITEMS` id is at implement time rather than assuming 14, and must not revert those hunks.
- **Deep-linking costs one artifact request on a hashed page load.** Requirement 10's observable — opening the page issues no artifact render — holds for `/tickets/{id}`; `/tickets/{id}#spec` deliberately opens and fetches that one panel, because requirement 16's spec link is meaningless against a closed `<details>`.
- **Epic pages pay a full backlog frontmatter scan.** Gated on `type: epic`, no lifecycle phase detection, and cheaper than the 30s poller's existing pass — but it is a per-request O(corpus) read, and a much larger backlog would want the polled snapshot instead.
- **`_parse_frontmatter` / `_parse_inline_str_list` are module-private.** Importing them is deliberate reuse of the canonical parser over a third hand-rolled scanner in `data.py`; promoting them to public names would touch `generate_index`'s API and its other callers, which is out of scope here.
- **Task 4 lands links to a route Task 6 adds.** Intermediate commits on the branch have three cards linking at a 404; the smoke test in Task 6 is what closes it.

## Acceptance

`GET /tickets/{id}` renders the seeded ticket's badges, body, and epic children, one collapsed panel per present artifact, none fetched until opened; an unknown id returns 404 and a non-local backlog backend renders unavailable on both routes. `cortex/lifecycle/<slug>/research.md` renders with `<slug>` escaped and no double-escaping across the shipped sanitization tests and the ten largest real artifacts. Every seeded feature card's backlog link and the board row's link-out resolve.
