# Plan: no-lifecycle-area-requirements-doc-so

## Overview

Author `cortex/requirements/lifecycle.md` as a template-conformant area doc and make `project.md`'s Conditional Loading row a bare path in the same change, so the row #454 landed can finally resolve; then relocate seven uncontested lifecycle-only bullets behind pointer stubs and add the regression test that would have caught an unresolvable routing row. Key decision: the doc and the row correction ship as one task because writing the doc without correcting the row leaves the defect open (verified executably in research) — they are not independently useful. The 2→3 edge is ordering-only and dissolves under worktree isolation, so the real shape is one heavy task then a two-task wave; under trunk the three tasks serialize.

## Outline

### Phase 1: Reachable doc (tasks: 1)
**Goal**: `cortex/requirements/lifecycle.md` exists, conforms to the area template, cites the seven previously-uncited lifecycle ADRs with status discipline honoured, and the loader resolves it for a lifecycle-tagged feature.
**Checkpoint**: `cortex-load-requirements --feature no-lifecycle-area-requirements-doc-so` prints `cortex/requirements/lifecycle.md` with no ` (skipped: file absent)` suffix, and the area validator returns `{"state": "pass", ..., "missing": []}`.

### Phase 2: Relocation and guard (tasks: 2, 3)
**Goal**: seven lifecycle-only items move out of `project.md` behind ≤200-byte pointer stubs while five contested items stay in full, and a repo-real regression test pins that every `## Conditional Loading` path resolves.
**Checkpoint**: `wc -c cortex/requirements/project.md` ≤ 26,918; the new test goes red when ` (annotation)` is appended to the lifecycle row in the real `project.md` and green when reverted; `just test` passes.

### Task 3: Regression test pinning that every `## Conditional Loading` path resolves
- **Files**: `tests/test_conditional_loading_paths_resolve.py` (create), `cortex/requirements/project.md` (transient mutation, reverted)
- **What**: Adds a pytest lint that reads the repo's real `cortex/requirements/project.md` and asserts every `## Conditional Loading` path exists on disk, closing the class of defect #454 shipped (a routing row whose path could never resolve, with no test able to see it). Discharges R9.
- **Depends on**: [1, 2] (write-serialization: cortex/requirements/project.md)
- **Complexity**: simple
- **Context**:
  - **The edge on Task 2 is ordering-only.** This task needs nothing Task 2 produces; it is sequenced after it because its mutation check writes to `cortex/requirements/project.md` and a concurrent relocation edit to the same file would be clobbered by the revert. Under worktree isolation each task holds its own copy and an executor may relax this to not-before; under trunk it must hold.
  - **Revert by restoring the appended text, not by `git checkout --`.** The mutation is a known one-line append; undo it in place. A `git checkout --` on `project.md` would discard Task 2's uncommitted relocation if the ordering assumption ever fails.
  - **Must import the loader's own parser** — `from cortex_command.lifecycle.load_requirements_cli import _parse_conditional_loading` — rather than re-implementing the split. Parser parity is what makes the mutation catchable: a test with its own lenient regex could strip a trailing annotation the loader keeps, pass, and miss exactly the defect it exists to prevent.
  - **Must read the real repo file**, not a `tmp_path` fixture. `tests/test_refine_session_ownership.py:240-251` writes a synthetic `project.md` under `tmp_path` and is explicitly **not** a discharge of this requirement. Repo-root idiom: `REPO_ROOT = Path(__file__).resolve().parent.parent`.
  - **Pattern reference**: `tests/test_backlog_grep_targets_resolve.py` — same shape (helper + `tmp_path` self-tests + one terminal test against the live corpus that is the load-bearing guard). Its docstring names the failure it prevents; do the same here.
  - **Scope is `## Conditional Loading` only.** `## Global Context` is out of scope by design: `skills/requirements/SKILL.md` states that listing a Global Context path before its file exists is valid, so asserting on it would be wrong.
  - Assert `(REPO_ROOT / path).is_file()` per parsed `(trigger, path)` pair; on failure report the offending trigger and path.

Then the mutation, run and reported: append ` (annotation)` to the lifecycle row in the real `cortex/requirements/project.md`, re-run — the test must go **red**; revert the append, re-run — it must go **green**, and `git diff cortex/requirements/project.md` must show the file unchanged from Task 2's output. A test that stays green under the mutation fails this task. Finally `just test` passes in full.

## Risks

- **The relocation half (Task 2) is contested by this feature's own research**, which found it nets zero content for correctly-tagged features and is strictly worse for wrong-tag ones, since `project.md` loads unconditionally today. The spec resolved this by relocating only the seven uncontested items and keeping the five normative ones in full, and by stating openly that the shrink's beneficiary is the ~82% of features that are *not* lifecycle-tagged (−3,670 B each), while lifecycle-tagged features pay +2,330 to +5,330 B. If you disagree with that trade, Task 2 is the task to cut — Phase 1 ships and closes the reachability defect on its own.
- **A new silent failure mode is introduced.** `review.md`'s no-match warning is boolean: an `observability`-tagged ticket touching an events.log parser matches `observability.md`, so the warning stays silent while the lifecycle content it needs never loads. R7 mitigates by keeping lines 61 and 65 in `project.md`; the residual gap is recorded in the spec's Open Decisions and deliberately not fixed here.
- **The new doc has no growth brake.** No token budget applies to area scope, `cortex/requirements/` is outside the reference-size ratchet, the validator is not wired into CI, and `review.md` §3a auto-appends on detected drift. The spec records this as a known exposure and declines to build the brake now on evidence-bar grounds.
- **Task 3's mutation check is the only thing separating a real guard from a decorative one.** A test that parses the row with its own regex instead of the loader's `_parse_conditional_loading` can pass while the loader still fails; the plan requires the mutation be run and its red/green result reported, not asserted.

## Acceptance

A lifecycle-tagged feature's `cortex-load-requirements` output lists `cortex/requirements/lifecycle.md` as a bare, resolvable path alongside `project.md` and `glossary.md`; that doc passes the area validator, cites all seven previously-uncited lifecycle ADRs with the proposed ones marked non-binding, and states its boundary against `observability.md` and `pipeline.md`. `project.md` is at least 3,000 bytes smaller, carrying seven pointer stubs with all five contested bullets intact. Appending an annotation to the lifecycle routing row turns `just test` red.
