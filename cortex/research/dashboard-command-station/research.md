# Research: dashboard-command-station

> Discovery research, 2026-07-21. Sizing: complexity `complex`, criticality `high` (8-agent cell; 6 core angles + adversarial dispatched — the Codebase angle was split consumer-side/producer-side on genuine distinctness, not to fill the cell). Requirements context loaded: `cortex/requirements/project.md`, `cortex/requirements/glossary.md` (verb fallback note: "no area docs matched for tags: []; loaded project.md only"), plus `cortex/requirements/observability.md` read directly as the governing area doc.

Topic: overhaul the existing dashboard (`cortex_command/dashboard/` — FastAPI + Jinja2 + HTMX, read-only, loopback) from an overnight-session monitor into a project command station: ticket board with blockers/deferred/epics, in-dashboard ticket reading (body + lifecycle artifacts), and a lifecycle landscape — all read-only; browser-side mutation, npm/React tooling, and auth are out of envelope.

## Research Questions

1. What minimal set of views turns the dashboard into a command station given the actual data shape? → **Three, sized to the data: a small honest triage Board (epic-grouped + flat ready list), a full-page Ticket Reader, and a minimal non-headline Landscape strip. The live set is near-empty (3 non-terminal of 403 backlog files; 0 open epics) against a large settled corpus (357 complete; 170/177 active lifecycle dirs already ended complete), so board chrome sized for volume (kanban columns, dependency graphs, hero metrics) is rejected; the board must degrade gracefully to a list.**
2. How should the dashboard acquire backlog/lifecycle data? → **Import `collect_items()` + `build_epic_map()` + `partition_ready()` in-process into `DashboardState` memory only, inside `_poll_slow`'s existing backend-gated block on the existing 30s cadence. Never write `index.json` (it stays a gitignored cache owned by writer verbs); no mtime gate. The feed is additive, not a replacement: critical review verified `collect_items()`'s returns cannot reproduce the two existing scans' outputs — `active_items` drops every terminal file and `all_items` carries only `{id, status, uuid}`, no title — so `parse_backlog_counts`/`parse_backlog_titles` are retained for their terminal-corpus consumers (the distribution bar's 6-bucket/401-file view; title lookups for completed features, 398/401 of which are terminal-only today [feature_cards.html:47; escalations_panel.html:19]).**
3. How is lifecycle phase derived at landscape scale, and what answers #306? → **Backlog-linked phase comes free from `collect_items()` (it calls `resolve_lifecycle_phase` per active item). The landscape ships only in #306's own fallback shape — dashboard-internal, in-memory, over the `active_ids`/`archive_ids` split `collect_items()` already computes. #169 is `status: complete` and resolved, not a gate: it shipped a predicate fix plus one manual sweep, with no recurring re-sweep mechanism, so 170/177 active dirs have already re-accumulated as completed-but-unswept since that sweep [cortex/backlog/169-fix-archive-predicate-and-sweep-lifecycle-and-research-dirs.md:5; justfile:231-232; commits 35caeb22, a5b223da] — the sweep-lag story the landscape strip would surface is real and structural, not a symptom of an outstanding fix (see Codebase Analysis, "#169 resolution"). Full per-dir events scanning across all ~177 dirs is not needed for v1.**
4. What does in-dashboard ticket reading require? → **A `/tickets/{id}` full page mirroring the `/sessions/{id}` precedent: frontmatter badge strip, markdown body via the existing `markdown.markdown(text, extensions=["fenced_code","tables"])` + `| safe` pipeline (no sanitizer — same trust boundary as morning reports, contingent on the loopback bind, see Decision Records), generic H2 rendering across both body-template generations, epic `## Children` linkification, and lifecycle artifacts (research/spec/plan/review) rendered per-request from `cortex/lifecycle/{slug}/` and `archive/{slug}/`. Rendering up to 5 markdown docs per request (≈58ms worst-realistic, measured against this repo's largest artifacts) is strictly more synchronous work than the precedent's single document — lazy per-artifact loading or a `run_in_executor` offload is the named mitigation for the spec to weigh. Slide-over is a deferred enhancement.**
5. Which hygiene issues are upstream prerequisites vs read-side? → **Upstream, ship first: ticket #230's `blocked_by:` underscore key is silently dropped by every reader — fix the file and add a warn-on-unrecognized-key guard in `generate_index.py`. Read-side only: quoting inconsistencies (readers already strip quotes) and stray priorities (`should-have`, `contingent` — dormant on terminal items; display-bucket unknowns to last). Candidate upstream tickets surfaced by critical review: export `_is_deferred` or teach `partition_ready` tags (tag-deferral is module-private today and invisible to readiness), and implement readiness.py's own docstring-promised `blocked by <id>: <status>` reason format, which no caller currently emits.**
6. How do new views fit the design system, polling budget, seed, and tests? → **New §-numbered panels in the parchment/carbon idiom with a backlog-specific badge map (the existing `_BADGE_CLASS_MAP` is keyed on the feature-status vocabulary, not backlog statuses); heavy partials set an explicit ≥30s `hx-trigger` (never inherit the 5s default — data changes at 30s cadence); four-layer tests per the existing pattern plus dedicated 200/404 route tests with a seeded fixture file; seed.py needs richer bodies and blocked-by/epic/deferred variety, and the board must take an explicit position on seed IDs 990–994 (they poison the live set when seeded).**
7. What phasing lands value earliest? → **1 hygiene fix → 2 ticket feed → 3 board + blocker/deferred surfacing (one PR in practice) → 4 ticket reader → 5 landscape strip — with seed/tests/docs shipped inside each phase, and the observability.md/app.py bind-address correction promoted to a correctness dependency of the no-sanitizer decision, not trailing doc polish.**

## Codebase Analysis

**Dashboard today.** FastAPI app with flat `@app.get` routes [cortex_command/dashboard/app.py:275-410]: `/`, `/health`, `/sessions`, `/sessions/{session_id}`, and 10 HTMX-polled `/partials/*`. Server-rendered Jinja2 resolved via `importlib.resources` through the regular package — never add `__init__.py` under `templates/` (namespace-package extraction breaks live references) [app.py:60-76]. `DashboardState` is a lock-free dataclass singleton mutated only by four asyncio poll loops (2s/1s/30s/5s) on one event loop [poller.py:62-119, 401-417; app.py:42]; handlers read cache only. The backlog surface today is aggregate-only: `_poll_slow` re-scans all `cortex/backlog/[0-9]*-*.md` every 30s via regex parsers extracting only `status`/`title` [poller.py:353-384; data.py:971-1082], gated on `resolve_backlog_backend(root)` resolved fresh each cycle with non-local backends standing down to empty state [poller.py:360-373; lifecycle_config.py:141-181] (the #321 pattern; the low-level parsers are NOT self-gating — gate discipline lives at every call site).

**Extension recipes (worked precedents).** New panel chain: parser in data.py → `DashboardState` field populated in a poll loop → `/partials/<name>` route → panel template → `<section hx-get hx-trigger hx-swap="morph">` registration in base.html [base.html:2151-2208] → additions to `PARTIAL_ROUTES` smoke list [tests/test_routes_smoke.py:40-51], template/structural tests [tests/test_templates.py], parser unit tests, poller gate tests. New page chain: the `/sessions/{id}` pattern — route with 404-on-missing [app.py:306-316], template `{% extends "base.html" %}` overriding `title`/`page_main`, hand-edited nav in base.html [base.html:2141-2144]. Route-ordering hazard: literal sub-paths must register before a `/{ticket_id}` catch-all. Trap: `pipeline_panel.html` is server-included, not polled — copying it yields a panel that never refreshes [base.html:2201-2203]. Reusable macros are minimal (`patterns/badge.html`, `feature-card.html`, `alert-banner.html`); DESIGN.md forward-references a not-yet-built `patterns/data-table.html` — the natural first macro for a board. `feature_cards.html:226-228` renders spec/plan/backlog artifact links as inert `href="#"` — named evidence that artifact *reading* is currently a dead end in the UI.

**Producer APIs (all pure reads, importable).** `collect_items(backlog_dir, lifecycle_dir) → (active_items, active_ids, archive_ids, all_items)` [cortex_command/backlog/generate_index.py:85-146] — no writes, no telemetry (both fire only from `main()` [generate_index.py:321-333]); 11.3ms measured over 401 files on this repo at a 3-item active set; synthetic re-measure scales linearly at ~0.12–0.14ms per active item (42ms at N=300, ~140ms at N=1000), and the `lru_cache(maxsize=128)` behind `detect_lifecycle_phase` stops amortizing across 30s cycles once the active set exceeds 128 — cost is then paid fresh every cycle. Per-item dict carries the full field set including `blocked_by` (read from hyphenated `blocked-by` [generate_index.py:197]) and `lifecycle_phase` resolved live via `resolve_lifecycle_phase` with `-paused` stripped [generate_index.py:176-184]. `build_epic_map(items)` is a pure in-memory grouping with a strict schema check [build_epic_map.py:93-173]. **Helper return shapes verified against the promised views (critical review):** `all_items` records carry only `{id, status, uuid}` — no title; `partition_ready`'s internal-non-terminal-blocker reason is the fixed literal `"blocked by non-terminal internal blocker"` [readiness.py:210-213] and the docstring's `blocked by <id>: <status>` format is emitted by no caller in the repo; tag-based deferral exists only in module-private `_is_deferred` [generate_index.py:74-76], unexported and unread by `readiness.py` (which never reads `.tags` — the #272 tag mechanism is invisible to it); `build_epic_map` children carry only `{id, spec, status, title}` [build_epic_map.py:158-163]; and `normalize_status` rewrites legacy `status: blocked` to `backlog` before item dicts exist [common.py:1234-1244], so blocked-ness derives from `blocked_by` resolution, never from status. `is_item_ready`/`partition_ready` are exported from `cortex_command.backlog` [backlog/__init__.py:16-20]; the board imports them for the eligibility partition — never re-encoding `cortex_command/backlog/triage.py` prose — while display labels are enriched by in-memory joins over feed data (blocked-why: `blocked_by` ids → sibling statuses; deferred: status ∪ tag membership; epic-child badges: id-join from four-field child records back to full items). `resolve_lifecycle_phase` is the ADR-0025 funnel already used by dashboard data.py [data.py:314; common.py:552-593]; cost per dir ≤5 stats + ≤4 reads, events.log corpus totals 673KB/173 files.

**Overnight linkage.** `OvernightFeatureStatus.backlog_id`/`backlog_uuid` tie run outcomes to tickets [overnight/state.py:81-87]; the poller already resolves active/latest session paths [poller.py:122-146]. Markdown precedent: single site, `markdown.markdown(report_text, extensions=["fenced_code","tables"])` rendered `{{ ... | safe }}`, computed per-request in the handler (not cached in state — the memory-growth pattern to preserve) [data.py:938-946; session_detail.html:56; app.py:306-316]. `pyyaml` is a base dep; `markdown<4` lives in the `[dashboard]` extra [pyproject.toml].

## Web & Documentation Research

- **Prior art**: `git-bug` / `git-issues` (YAML-frontmatter markdown files, single local binary, no DB) explicitly position a read-only web board as "a monitoring tool for AI agent projects" — this project's exact niche (https://github.com/git-bug/git-bug, https://news.ycombinator.com/item?id=47973644). Obsidian Kanban plugins validate frontmatter-as-source-of-truth. Linear/GitHub Projects conventions worth borrowing: group-by (status/epic/priority) with optional swimlane, collapse/hide empty columns (https://linear.app/docs/board-layout). In read-only boards the value is grouping/filtering/glanceability — spend nothing on interaction chrome.
- **HTMX**: `hx-push-url` for distinct bookmarkable views, `hx-replace-url` for filters; nothing in the codebase uses either yet — another reason to ship the full page first. Idiomorph preserves `<details>`/focus state but not scroll position; known pitfall to test on any independently-scrolling board region (https://htmx.org/extensions/idiomorph/, https://github.com/bigskysoftware/htmx/issues/1671).
- **Accessibility**: `role="grid"` on a read-only board is a documented anti-pattern (arrow-key expectations, custom handler burden) — use semantic sections/headings/lists with normal Tab order (http://adrianroselli.com/2020/07/aria-grid-as-an-anti-pattern.html, https://www.w3.org/WAI/ARIA/apg/patterns/grid/).
- **Markdown/XSS**: python-markdown's docs state output is unsanitized (https://python-markdown.github.io/sanitization/); bleach is unmaintained; nh3 is the modern sanitizer. Adversarially adjudicated for this repo: rejected — see Decision Records.
- **Tailwind Play CDN** is documentation-labeled dev-only but supports v4 `@theme` inline blocks; the standalone-CLI vendoring path exists if offline-reliability ever becomes a hard requirement (https://tailwindcss.com/docs/installation/play-cdn).
- **Dashboard-sprawl evidence**: information overload is the dominant dashboard failure mode; match visualization to data cardinality — with single-digit open items, full board chrome is the failure, and graceful degradation to a list is the fix (https://www.nngroup.com/articles/visibility-system-status/, https://www.nngroup.com/articles/status-tracker-progress-update/).

## Architecture

### Pieces

- **Ticket feed** — the single in-memory snapshot of backlog truth (active items, epic map, readiness partition, deferred markers, blocked-why joins) that every command-station view reads; owns backend-gating and the seed-ID policy; runs alongside the two retained counts/titles scans, whose terminal-corpus consumers (distribution bar, completed-feature title lookups) the feed's active-only helpers structurally cannot serve.
- **Triage board** — the "what should I work on, what's blocked and why" panel: epic-grouped children with refined/blocked/deferred badges plus a flat ready list, degrading to a plain list at small counts.
- **Ticket reader** — the deep-linkable per-ticket page: frontmatter badge strip, rendered body, linked lifecycle artifacts (research/spec/plan/review), epic children linkified; computed per-request, never cached.
- **Landscape strip** — the minimal archive-vs-active health line derived from data the feed already holds; the honest home for the settled-corpus story, which #169's predicate-fix-plus-one-time-sweep (no recurring mechanism) confirms is real and ongoing rather than an artifact of an unfixed bug.
- **Hygiene guard** — the upstream data-correctness fix (#230 key spelling) plus a warn-on-unrecognized-key tripwire so future hand-edits fail loudly instead of silently.
- **Fixture & test surface** — seed variety (bodies, blockers, epics, deferred, lifecycle-linked slugs) and the four-layer test additions each phase owes, including dedicated reader 200/404 coverage.
- **Docs & requirements reconciliation** — the observability.md regather (description, inputs, panels, bind-address) and app.py docstring fix that the no-sanitizer decision depends on, plus docs/dashboard.md panel entries.

### How they connect

The ticket feed runs inside the existing 30s slow poll behind the existing backend gate and writes only to `DashboardState` memory — it adds one scan beside the two it cannot replace (counts/titles serve terminal-corpus consumers the feed's active-only helpers structurally miss), and nothing it produces is ever written to disk (`index.json` remains a writer-verb-owned cache the dashboard never touches or depends on). The triage board and landscape strip are pure renderings of feed state on their own ≥30s HTMX triggers; the board's eligibility partition and epic grouping come from the same imported producer helpers the CLI verbs use — so the decision logic cannot drift from the dev-skill triage — while display labels are feed-layer joins the helpers don't provide (epic-child badges join child ids back to full item records; blocked-why joins `blocked_by` ids to sibling statuses; deferred unions `status: deferred` with `deferred`-tag membership). The ticket reader is a per-request page (sessions-detail precedent): it resolves one item from feed state, reads body and lifecycle artifacts from disk at request time through `resolve_lifecycle_phase`-consistent paths (checking `archive/` too), and renders markdown through the one existing pipeline — its safety posture is inherited from the loopback bind, which is why the docs/docstring reconciliation is a dependency, not an afterthought. The hygiene guard sits upstream of the feed's correctness (a dropped blocker key would flow silently into every view); the fixture surface feeds visual development of board and reader alike but intersects the feed through the seed-ID policy, which must be decided, not left emergent.

## Decision Records

**Write boundary.** The dashboard acquires ticket data by importing `collect_items()` in-process, in-memory only. Regenerating `index.json` from the dashboard was rejected: the offered precedent (`ready.py:94-126`) is actually warn-don't-write, ADR-0011 assigns writes to writer-authorized verbs, and #306's cited untracking decision forbids shared-aggregate rewriting. The mtime gate was also dropped — the poller already re-scans unconditionally at 30s, and a gate adds a clock-correctness surface (git checkouts reset mtimes) to save ~11ms. Direct pyyaml parsing was rejected as a divergent second implementation of readiness/phase logic (solution-horizon test).

**Landscape scope.** Downgraded from headline view (UX angle's Candidate B centerpiece) to a minimal strip over the feed's existing active/archive split, per #306's close-out and fallback clause. #169 (complete) resolves the dependency this decision once deferred: it fixed the archive predicate and ran one manual sweep, but added no recurring re-sweep mechanism, so the active/archive split keeps re-accumulating sweep-lag by design of the current tooling — 170/177 active dirs are already completed-but-unswept again, all post-dating the sweep [cortex/backlog/169-fix-archive-predicate-and-sweep-lifecycle-and-research-dirs.md; justfile:150-152, 231-232]. The archive-heavy corpus is real content, and the unswept residue is a genuine, ongoing gap rather than a bug awaiting a fix — the strip's evidence stands as reported.

**Sanitizer.** No nh3. Ticket bodies share the morning-report trust boundary (same authors, same repo, rendered by the same pipeline), the surface is loopback-bound, and "accidental payload in a ticket body" is a hypothetical, failing the front-door bar against a named cost (a new capped dependency in every consumer's `requires-dist`). Coupled obligation: the stale 0.0.0.0 claims (observability.md:107, app.py:11 docstring) must be fixed in the same epic, because the decision is contingent on loopback.

**Reader shape.** Full page `/tickets/{id}` first (deep-linkable, poll-isolated, precedent-matching); slide-over deferred as strict enhancement. Existing markdown engine kept (`fenced_code`+`tables`; extend extensions before ever swapping engines). **Board rendering.** Semantic sections/lists, no `role="grid"`, no drag affordances, no dependency graph (~4–9 sparse historical edges — badge + reason string instead), no volume-hero metrics; explicit degradation to flat list at small counts.
